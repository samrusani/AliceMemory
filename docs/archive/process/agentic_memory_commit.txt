
Alice vNext Sprint Prompt: Agentic Memory Commit + Inline Review

Sprint Objective

Alice is agent-first. Users should not be forced to open /vnext every time they want something remembered.

The current model is too conservative for day-to-day second-brain usage:

agent/user says something important
→ candidate memory
→ /vnext manual review
→ accepted memory

That is safe, but too much friction.

This sprint should introduce trusted agentic memory commit and inline review so that when the user explicitly says “remember this,” “save this,” or “add this to memory,” Hermes/OpenClaw/custom trusted agents can commit memory through Alice Core immediately, without requiring dashboard review.

However, this must not become uncontrolled direct database mutation.

The correct model is:

Trusted agent requests memory commit
→ Alice policy checks it
→ Alice writes trusted memory if allowed
→ Alice preserves provenance, audit trail, sensitivity, domain, and undo/correction path
→ /vnext shows the memory in audit/history, but review is not required

The dashboard remains the audit, correction, review, and troubleshooting cockpit, not the normal workflow for explicit user memory.

Core Concept: Memory Write Modes

Add first-class memory write modes.

1. commit

Trusted memory is written immediately.

Used when:

user explicitly says “remember this”
trusted agent submits on behalf of user
policy allows domain/sensitivity/action
provenance is attached
memory text is clear

2. confirm_inline

Agent must ask the user inline before committing.

Used when:

memory is sensitive
memory affects high-impact domains
memory contradicts existing active memory
memory is important but potentially ambiguous
policy requires confirmation

Example:

Hermes: “This sounds like a sensitive family memory. Should I save it?”
User: “Yes.”
Hermes calls Alice commit endpoint with confirmation token.

3. propose_review

Memory goes to /vnext review queue.

Used when:

source is external/untrusted
agent inference is low confidence
agent is not trusted enough
memory is broad/ambiguous
memory is generated from research, PDFs, browser clips, email, Telegram forwards, etc.

4. reject

Alice refuses the memory write.

Used when:

agent lacks permission
source is prompt-injection content
domain/sensitivity policy blocks it
memory attempts to store secrets unsafely
memory violates hard policy

⸻

Auto-Commit Rules

Auto-commit allowed when all are true

user intent is explicit: “remember/save/store/add this to memory”
agent has trusted_local_agent or admin_agent permission
source is direct user instruction or trusted agent session context
domain is allowed for the agent
sensitivity is public/internal/private, not restricted
memory has clear canonical text
provenance is attached
no unresolved contradiction requiring confirmation
no policy block

Inline confirmation required when any are true

sensitivity is confidential, highly_sensitive, sacred, regulated, or unknown-high-risk
domain is health, family, spiritual, legal, financial, regulated, or confidential
memory contradicts an active trusted memory
memory changes a durable project decision
agent confidence is medium
user wording is unclear but likely important

Dashboard review required when any are true

source is external/untrusted
memory is inferred from browser clip/PDF/email/Telegram forward/web page
agent is project_scoped_agent and memory is outside project scope
agent is memory_proposal_agent but not trusted_local_agent
confidence is low
memory is bulk-generated
memory is a broad synthesis from many sources

Always blocked

read_only_agent memory writes
direct trusted memory writes from untrusted external content
prompt-injection instructions stored as operational memory
secret/token/API key storage unless explicitly classified and protected
attempts to bypass policy
attempts to mutate database outside Alice Core APIs

5. Inline Confirmation Flow

Add a durable confirmation flow for sensitive/ambiguous memory.

Flow:

agent attempts commit
Alice returns confirmation_required with confirmation_id
agent asks user inline
user says yes/no/edit
agent calls confirm endpoint
Alice commits, rejects, or updates memory
event log records full flow

Confirmation record should include:

confirmation_id
proposed_memory_text
domain
sensitivity
policy reason
agent_id
created_at
expires_at
status: pending/confirmed/rejected/expired

Acceptance criteria:

Sensitive memory returns confirmation_required.
Confirmation token can be accepted.
Confirmation token can be rejected.
Expired confirmation cannot be used.
Confirmed memory commits with audit trail.
Rejected confirmation does not create trusted memory.

6. Undo / Forget / Correct

Frictionless memory requires frictionless correction.

Add flows:

Undo

Undo last committed memory from this agent/session/user.

Should not hard-delete by default. Prefer:

status = superseded / archived / undone
revision event created

Forget

User explicitly asks Alice to forget a memory.

Behavior should be policy-governed:

soft-delete/archive by default
hard-delete only if supported and explicitly confirmed

Correct

User says “Actually, update that memory to X.”

Creates revision:

old text
new text
reason
actor
timestamp

Acceptance criteria:

Hermes can undo last committed memory.
Hermes can correct a memory.
Hermes can request forget.
All actions are event logged.
Context packs respect undone/forgotten/superseded state.
Audit trail remains inspectable.

This sprint should be measured by UX and safety.

Functional success

Hermes can commit an explicit “remember this” memory without /vnext review.
Hermes can ask inline confirmation for sensitive memory.
Hermes can undo/correct/forget a recent memory.
OpenClaw can commit project-scoped memory but cannot commit personal memory.
External browser/Telegram/PDF content still routes to proposal/review, not direct trusted memory.

Friction success

User receives confirmation in the same Hermes conversation.

Safety success

0 critical privacy leaks.
