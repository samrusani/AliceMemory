# Alice v0.13.1 Release Notes

**Replicated benchmark, faster SQLite at scale, reference integrations.**

`v0.13.1` is the Phase 4 core-roadmap release. (The `v0.13.0` tag exists
but was never published: its tree failed the release gate on a changelog
formatting requirement, and stable tags are immutable by policy, so the
number was superseded rather than the tag moved.) It changes retrieval behavior
in exactly one disclosed, dormant-by-default way (a trace-only diagnostic
under the aggregation gate) and otherwise invests in evidence, scale, and
integration surface.

## Replicated LongMemEval baseline

The published LongMemEval_s claim is now a replicated measurement:
**81.2% mean over three independent full runs (80.8% / 81.0% / 81.8%)** on
the published `v0.12.0` code, same configuration as the historical run
(gpt-4o chain-of-thought reader, official judge protocol,
text-embedding-3-small). Every run scored 500/500 with zero errors;
per-question evidence for all three runs is committed under
`docs/benchmarks/longmemeval/replication-v0.12.0-2026-07-19/`. The
historical single-run 79.4% remains on record as dated evidence. Abstention
subset variance across runs is disclosed rather than smoothed.

> **Correction (2026-10-01):** The 81.2% figure above, and the 79.4% single
> run before it, have a known issue. In the LongMemEval_s data the id of every
> evidence session starts with `answer_`, and the harness showed the reader
> model each session's id, so the model could see which sessions held the
> evidence. We have not measured how much this helped, so both figures may be
> overstated by an unknown amount. See the Benchmark section of the README.

## SQLite vector scale

- `search_memories_vector` is rewritten as a vectorized two-phase scan
  whose results are bit-identical to the previous per-row algorithm,
  proven by a differential oracle over an adversarial corpus.
- A process-local resident vector cache (invalidated by a transactional
  stamp token on every embedding write, clear, and redaction) removes the
  per-query blob streaming that dominated large-corpus recall: the vector
  stage at 100k memories drops from ~2.1s to **385–465ms warm**, inside
  **754MB peak / 760MB steady** resident memory with a 1024MB default cap
  (`ALICEBOT_SQLITE_VECTOR_CACHE_MAX_MB`) and a full off-switch
  (`ALICEBOT_SQLITE_VECTOR_CACHE=off`) that restores prior behavior
  bit-identically.
- The SQLite bootstrap schema gains one additive one-row table
  (`embedding_stamp`); pre-existing database files degrade safely to the
  previous stateless scan until re-bootstrapped. Postgres is unchanged.
- The scale benchmark record is corrected honestly: end-to-end recall at
  100k improves ~22% (2253.7 → 1764.4ms p50), and the remaining wall is
  FTS/source search, not the vector stage
  (`docs/benchmarks/scale/README.md`).

## Reference integrations

- `docs/examples/mcp_quickstart.py`: a stdlib-only runnable that spawns the
  packaged SQLite MCP server, verifies the eleven-core-tool surface against
  live `tools/list`, and round-trips capture → commit → recall over stdio.
- `docs/examples/openai_agents_sdk_tool.py`: Alice memory tools in the
  OpenAI Agents SDK function-tool shape (no SDK dependency), authenticated
  with real per-agent `alice_sk_…` keys. Its integration smoke proves
  tampered-key rejection and the `read_only_agent` write refusal
  server-side.
- Both are smoked in CI; `docs/integrations/reference-paths.md` carries the
  new adoption paths.

## Multi-session counting: honest groundwork, no uplift claim

Count-intent recognition (cardinality, frequency, cadence, numeric-value)
lands with a bounded, provenance-deduplicated candidate statistic recorded
in the retrieval trace only — explicitly marked `is_answer=false`. No
reader-facing count, MCP change, or OpenAPI change exists, because
measurement showed a memory row is not proven to equal one queried
occurrence: both deterministic development arms measured 0/14
answer-sufficient, the benchmark-closure NO-GO is recorded in the Phase 4
Sprint 4 handoff, and a future design needs a persisted one-unit-per-member
invariant. This release makes no multi-session synthesis uplift claim.

## Candidate verification

The integrated carrier passed 3,847 unit tests, the full role-separated
PostgreSQL integration suite including the new auth smokes, 135 LongMemEval
model-free tests, the LongMemEval evidence replay, the default-surface
smoke, and the web matrix, with every carrier increment adversarially
reviewed (two independent review rounds each for the vector cache and its
memory posture) — reproduced by the release engineer on the exact tree
before this release was cut.

## Upgrade

No Alembic migrations; the Postgres schema is unchanged from `v0.12.0`.
SQLite gains one additive bootstrap table on normal startup. No operator
action is required; the vector cache's memory posture and off-switch are
documented above. All documented entry points are unchanged.

wheel and source distribution carry PyPI's integrity attestations, which
bind each file to this repository, the release tag, the publishing workflow,
the exact commit, and the protected `pypi` environment — verifiable on the
project's PyPI page. Their exact SHA-256 digests are recorded in
