# Alice v0.23.1 Release Notes
<!-- alice-release-state: {"schema_version":"alice_release_document_state_v1","version":"0.23.1","publication_status":"published","checksums_status":"recorded"} -->

**Take this release if you connect Codex or Hermes to a SQLite vault that holds agent
keys. Once the vault holds a key, a call that does not carry `ALICE_AGENT_API_KEY` is
refused, and the v0.23.0 agent guide gave Codex no route for the key and told Hermes
users to export it in the shell. The guide now names a route for each host. Nothing
behaves differently: the code is v0.23.0's apart from one docstring and the version
number, there is no new tool, command or setting, and there is no migration. Everyone
else can stay on v0.23.0. See "What to do after upgrading".**

- The v0.23.0 guide named no way to give the Codex MCP server the key. Codex passes a
  stdio server only `HOME`, `PATH`, `LANG` and a few other names, so a key exported in
  the shell that starts Codex does not reach Alice by itself. The guide now names the
  alice table's `env_vars` or `env`.
- The v0.23.0 guide told Hermes users to export the key in the launchd session, the
  terminal or the wrapper that starts the host, and said the config's `env` map is not
  the place for a secret. The guide now names the `env` map of `mcp_servers.alice`,
  which the Hermes page describes.
- The docstring of `_own_env` in `host_install.py` no longer says install writes a
  reference to the agent key.

## What to do after upgrading

1. **Upgrade the copy your hosts run** (`uv tool upgrade alice-memory`, or
   `pip install -U alice-memory` in the environment they use), check it with
   `alice-memory --version`, and restart your hosts. Nothing else is required.
2. **No migration.** A vault that v0.23.0 wrote opens in v0.23.1, and a vault that
   v0.23.1 has opened opens in v0.23.0. PostgreSQL stays at revision `20261011_0097`.
3. **Codex or Hermes on a vault that holds a key.** Skip this step if the vault holds no
   key. Otherwise check that the host's MCP server gets `ALICE_AGENT_API_KEY`. For Codex,
   name it in the alice table's `env_vars` (`env_vars = ["ALICE_AGENT_API_KEY"]`) to
   forward the shell's value, or set it in the same table's `env`. For Hermes, put it in
   the `env` map of `mcp_servers.alice`. A re-run of `alice-memory install` keeps these
   entries, and for Hermes never prints the key. To check one, make a call from the host:
   a call that did not receive the key is refused, and a call that did is answered. The
   guide's text on the session-start hook is unchanged: the hook is a separate process and
   reads the key from its own environment.
4. **Claude Code plugin.** The marketplace file on `main` pins the v0.23.0 tag commit
   until a change after this release moves it, so a marketplace install runs v0.23.0
   code until then.

   > **Update (2026-11-01):** v0.23.1 is published, and the marketplace file on `main` now pins the v0.23.1 tag commit, so the marketplace install runs v0.23.1. The copy inside the v0.23.1 tag still pins v0.23.0, so add the marketplace from the repository, not from a checkout of the tag.

## The agent key section of the guide

The section "Agent keys on the SQLite vault" of `docs/alpha/agent-integration.md` lists,
for Claude Code and the plugin, Codex and Hermes, how the key gets into the environment
of the host's MCP server:

- **Claude Code and the plugin:** the `env` map of the host's MCP entry, or the launch
  environment of your user session. This is as in v0.23.0.
- **Codex:** `env_vars = ["ALICE_AGENT_API_KEY"]` in the alice table forwards the shell's
  value, and the same table's `env` sets it. A re-run of install keeps both.
- **Hermes:** the `env` map of `mcp_servers.alice`, which the Hermes page describes. A
  re-run of install keeps it and never prints it.

The section also says that a key written into a host's config file is stored there as
plain text that your OS user can read, which is the same reach keys already leave open,
and that none of these routes has been run against a real host in this repository.

## Other changes

The docstring of `_own_env` in `apps/api/src/alicebot_api/host_install.py` said that
install writes the agent key's environment reference. Install writes the value of
`ALICE_MEMORY_DATA_DIR` and no key and no reference to one, as in v0.23.0, and the
docstring now says so. It is the only file under `apps/api/src` that differs from
v0.23.0, and its code is the same.

The other changes are outside the PyPI package. The unit tests run as six CI shard jobs
instead of five. `scripts/showcase_bench.py` mints its keys through the entry point of
`alice-memory keys create` in process. The first job of `publish-pypi.yml` and the job
of `publish-recheck-rehearsal.yml` have a `timeout-minutes` of 200, up from 180.

## Behaviour changes an integrator will notice

None. No tool, command, setting or route is added or changed, and the tool counts are
those of v0.23.0.

## Security

This release was checked with automated security scanning and internal adversarial
review, findings triaged and fixed. No one outside the project has audited the code.

No security advisory is planned for this release. The change to the guide moves where a
key is kept for two hosts: in the host's config file, as plain text that your OS user can
read. Keys tell Alice which agent is asking and limit what Alice returns to that agent.
They do not stop a process that runs as your OS user from reading the vault file.

## What this release does not claim

It does not claim that any of the routes works on a real host: the guide says none has
been run against one in this repository. It does not claim that Hermes passes your
shell's environment on to the server, only that this repository does not show it, so the
guide tells you not to rely on an exported variable. It does not claim that a key in a
config file is protected from other processes that run as your OS user. It does not claim
any change in what Alice does: only a docstring differs in the package.

## Install

```bash
pip install alice-memory==0.23.1 && alice-memory install
```

With uv: `uvx alice-memory install`.
