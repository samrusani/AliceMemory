# Alice v0.21.1 Release Notes
<!-- alice-release-state: {"schema_version":"alice_release_document_state_v1","version":"0.21.1","publication_status":"published","checksums_status":"recorded"} -->

**Take this release if you import notes or capture text that holds part, order or
ticket codes such as `SK-2291`, if your notes may hold a token that sits right after
an underscore, or if you run the review console from a v0.21.0 checkout. The
credential check no longer reads a short code that starts with a credential marker,
or a name such as `npm_config_cache`, as a credential, so `alice_capture` accepts the
text and `alice-memory import-markdown` keeps the line and the file. It reads a token
right after an underscore, which v0.21.0 stored. The web console moves to Next.js
16.4.1 for two advisories. There is no new tool, command or setting, and there is no
migration. See "What to do after upgrading".**

- v0.21.0 refuses a capture and withholds an import line when the text holds a code
  such as `SK-2291` or a name such as `npm_config_cache`, and it skips a file whose
  name holds one. v0.21.1 accepts and keeps them.
- v0.21.0 stores a token that sits right after an underscore (`_ghs_` and a token,
  `TOKEN_npm_` and a token). v0.21.1 refuses or withholds it.
- The console in v0.21.0 uses Next.js 16.3.8, which two advisories published on
  2026-10-22 affect. v0.21.1 uses 16.4.1. The PyPI package does not include the
  console.

## What to do after upgrading

1. **Upgrade the copy your hosts run** (`uv tool upgrade alice-memory`, or
   `pip install -U alice-memory` in the environment they use), check it with
   `alice-memory --version`, and restart your hosts. Nothing else is required.
2. **No migration.** A vault that v0.21.0 wrote opens in v0.21.1, and a vault that
   v0.21.1 has opened opens in v0.21.0. PostgreSQL stays at revision `20261011_0097`.
3. **Notes with part or order codes.** A note that v0.21.0 imported keeps the lines it
   withheld. Run `alice-memory import-markdown` on the folder again to import a file
   that v0.21.0 skipped for its name. To replace a note that was imported with
   withheld lines, preview with `--supersede --dry-run`, then run with `--supersede`,
   which replaces the earlier import of the same path.
4. **Run `alice-memory doctor`** on each SQLite vault. It flags a source that holds a
   token right after an underscore, which v0.21.0 stored. Rotate each credential it
   lists and remove the source with `alice-memory sources delete <id>`; the
   [known limitations page](../alpha/known-limitations.md) lists what a delete keeps.
   `doctor` reads sources and not the text of a memory, so it does not flag a memory
   that was committed with such a token.
5. **Console.** If you run the console from a v0.21.0 checkout or an earlier one,
   check out v0.21.1, run `pnpm --dir apps/web install` and then
   `pnpm --dir apps/web build`, and keep the console reachable only from this machine.
6. **Claude Code plugin.** The marketplace file on `main` pins the v0.21.0 tag commit
   until a change after this release moves it, so a marketplace install runs v0.21.0
   code until then.

The copy inside the v0.21.1 tag still pins v0.21.0 and the copy inside the v0.22.0 tag still pins v0.21.1, so add the marketplace from the repository, not from a checkout of a tag.

## Credential markers

One check reads a list of token markers (`ghp_`, `gho_`, `ghs_`, `ghu_`, `github_pat_`,
`glpat-`, `npm_`, `sk-`, `xoxb-`, `xoxp-`, `xoxa-`, `xoxs-`) at `alice_memory_commit`,
`alice_capture`, `alice-memory import-markdown`, `alice-memory import-chatgpt` and the
promotion credential floor. v0.21.0 read the bare marker, so any word that started
with one counted as a credential: `SK-2291`, `sk-2291 is current`, `SK-229`, and the
name `npm_config_cache`.

**No longer read.** A marker counts only when a floor of token characters follows it:

- 36 letters and digits for `ghp_`, `gho_` and `npm_`.
- 36 letters, digits, dots, hyphens or underscores for `ghs_` and `ghu_`. That is the
  class GitHub publishes for `ghs_`, and it covers the stateless installation token (`ghs_`,
  a numeric app id, an underscore and a JWT, about 520 characters). `ghu_` takes the
  same class and floor by our choice, because GitHub announced a format change for it
  without details.
- 82 for `github_pat_`, 20 for `glpat-` and `sk-`, and 10 for the four Slack markers.

For `github_pat_`, `glpat-`, `npm_`, `sk-` and the Slack tokens we found no published
minimum, so each floor follows the shapes seen and public scanning rules, and is no
longer than the shortest of them. The commit gate's own `sk-` rule, which read `sk-` and 8
characters, takes the floor of 20, so `SK-20260301`, `SK-2025-0618` and `SK-2291-REV`
are no longer read as keys.

**Now read.** v0.21.0 hid a token right after an underscore, because its lead boundary
counted an underscore as part of a word. v0.21.1 reads `ghs_`, `ghu_`, `gho_`, `npm_`,
`glpat-` and `github_pat_` tokens after an underscore, or after a word and an
underscore (`_ghs_` and a token, `TOKEN_npm_` and 36 characters). The commit gate
already refused `_ghp_`, `_sk-` and `_xoxb-` tokens through its own prefix rules, so
for those three only the promotion credential floor changes.

**The boundary that stays.** A marker glued directly onto a letter or a digit is part
of a word and is not read, as in v0.21.0: a letter or a digit followed by a `ghs_`
token. A short name with an underscore before it (`PART_SK-2291`, `deploy_ghu_config`)
is not read either, because too little follows the marker. A `ghs_` or `ghu_` followed
by 36 or more letters, digits, dots, hyphens or underscores is read, as it was in
v0.21.0 and as GitHub's own pattern reads `ghs_`, so a snake case name that long after
the marker is read too.

**Unchanged.** The `ssh-rsa` and `ssh-ed25519` markers, the carve-outs, the `ghp_` and
`xoxb-` prefix rules (8 or more characters after them) and the AWS key id rule. The
credential detector still reads a lower-case `sk-` followed by 8 or more characters
that hold a digit, so a lower-case code of `sk-` and 8 digits is still refused. The
upper case code `SK-20260301` is not.

## The web console and Next.js 16.4.1

The web console's Next.js moves from 16.3.8 to 16.4.1, and `eslint-config-next` moves
with it. 16.4.1 fixes two advisories published on 2026-10-22: a critical one (remote
code execution in the Image Optimization API when SVG files are used) and a high one
(denial of service in the App Router through Server Actions). The CHANGELOG names
both. The console in v0.21.0 and earlier uses an affected version. The PyPI package
does not include the console, so `pip install alice-memory` is not affected. The
v0.21.0 notes carry a dated update that tells a v0.21.0 checkout to run from `main` or
to set the two versions by hand; with v0.21.1 you can check out the tag instead.

## Behaviour changes an integrator will notice

- `alice-memory import-markdown` keeps a line with a code such as `SK-2291` or a name
  such as `npm_config_cache`, where v0.21.0 stored `[withheld: credential material]`
  in its place, and imports a file whose name holds such a code, where v0.21.0 skipped
  the whole file. `skipped_credentials` and `skipped_credential_items` in its receipt
  no longer count them. `alice-memory import-chatgpt` keeps a message with such a code.
- `alice_capture` accepts text with such a code, where v0.21.0 answered
  `tool_request_failed`. `alice_memory_commit` stores it, where v0.21.0 answered
  `rejected` with `unsafe_secret_storage`.
- The same two tools and both imports now refuse or withhold a token right after an
  underscore, which v0.21.0 accepted.
- Texts that change, from the comparison tables of the credential tests. Refused in
  v0.21.0 and accepted now: `SK-LEARN is the old name`, `sk-learn_v2 and friends`, an
  `sk-` followed by 17 letters, a FIDO key type name cut short by one letter, and every
  short code and name above. Accepted in v0.21.0 and refused now: `_ghs_`, `x_ghs_`, `_ghu_`, `_gho_` and
  `TOKEN_npm_` followed by 36 characters, `_glpat-` followed by 20 and `_github_pat_`
  followed by 82, at the commit gate and the promotion credential floor; `_ghp_`
  followed by 36, `_sk-` followed by 20 and `_xoxb-` followed by a Slack token body,
  at the promotion credential floor only.
- Not changed: a `ghs_` or `ghu_` followed by 36 or more letters, digits, dots, hyphens
  or underscores is refused, as it was in v0.21.0.
- The one file under `apps/api/src` that differs from v0.21.0 is the credential check.
  The other changes are documentation (the v0.21.0 post-publication record and two
  benchmark pages), tests, the mutation manifest and the version strings.

## Security

This release was checked with automated security scanning and internal adversarial
review, findings triaged and fixed. No one outside the project has audited the code.

The change a security-minded reader will care about is the underscore. In v0.21.0 a
token right after an underscore was stored by `alice_memory_commit`, `alice_capture`
and both imports, and the promotion credential floor did not hold it back. v0.21.1
refuses it. A vault that v0.21.0 wrote may hold one, so run `alice-memory doctor` and
rotate what it lists.

## What this release does not claim

It does not claim that every credential is read. A marker followed by fewer token
characters than its floor is not read, and a marker glued onto a letter or a digit is
not read. The floors of `github_pat_`, `glpat-`, `npm_`, `sk-` and the Slack tokens are
not a published minimum. It does not claim that a vault holds no token: lines that
v0.21.0 withheld stay withheld, a memory that was committed with a token right after
an underscore stays stored, and `doctor` does not read memory text. It does not claim
that the console has no other advisory, only that the two named in the CHANGELOG are
fixed.
