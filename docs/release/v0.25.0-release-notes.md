# Alice v0.25.0 Release Notes
<!-- alice-release-state: {"schema_version":"alice_release_document_state_v1","version":"0.25.0","publication_status":"pending","checksums_status":"pending"} -->

**An agent that shares a lesson now hears what became of it and sees the closest published lessons when it writes one. This is also a security release for installs that use agent keys on the PostgreSQL stack.**

## What to do after upgrading

1. Upgrade the copy your hosts run with `uv tool upgrade alice-memory` or `pip install -U alice-memory`, check `alice-memory --version`, and restart the hosts.
2. No database migration is needed.
3. If your trusted key used to change the brain charter's promotion policy, lower its sensitivity, or correct a review candidate or a `private_only` memory, use the owner or an unbound `admin_agent` key. A writer can still correct its own waiting confirmation within the confirmation window. To change a stored source's sensitivity or a connector's default sensitivity, use the owner or an unbound `admin_agent` key. Keep creates within your key's sensitivity ceiling, or use an authorized key with a ceiling that covers the requested label.
4. If your integration reads `alice_lessons`, a lesson commit or a waiting review, handle the new `yours`, `lesson` and `similar` fields where they apply. A key that is neither the writer nor a decider no longer sees a waiting lesson.
5. If you run the web console from a checkout, run `pnpm install --frozen-lockfile` in `apps/web`.
6. The Claude Code marketplace pin moves to v0.25.0 in the post-publication change.

## Lessons

A keyed writer can use `alice_lessons` to see how many readable lessons are waiting and how many were published or closed without publication in the last seven days. It shows up to three recent unpublished decisions with their reasons when available. v0.24.1 returned published matches without a writer outcome summary.

An MCP lesson commit and its waiting review show up to three readable published lessons, with words, paths or vectors as the reason for each match. Review lists also show the waiting draft's fields and compute matches for the first ten waiting lessons. v0.24.1 returned the commit receipt and review queue without similar lessons.

Waiting, private-only and rejected lessons and their decision reasons are visible to their writers and authorized deciders. Other callers get the missing-item answer or the existing idempotency conflict. v0.24.1 let other readers within the lesson's read limits see waiting or rejected lessons in review and audit. Use `alice_memory_correct` to decide a waiting lesson. See [shared lessons](../alpha/shared-lessons.md#review-and-retire).

## Keys and permissions

- Changing the brain charter's promotion policy or lowering its sensitivity requires memory review standing. An admitted caller without that standing keeps the stored promotion policy by omitting it or passing null. A replacement promotion setting that its reader rejects is refused. v0.24.1 let admitted callers replace promotion settings and lower sensitivity, including saving promotion settings the reader refused.
- Correcting a review candidate, a `private_only` memory or a `needs_review` memory without a pending confirmation requires review standing. A caller with review standing can correct a waiting confirmation at any time, and the writer can correct it within the confirmation window. A successful correction resolves the confirmation record, and missing, non-text, timezone-free or unreadable deadlines count as expired for confirming and correcting. v0.24.1 let corrections activate waiting rows without these standing checks and left the confirmation record pending.
- Project creation, brain charter saves, source reviews and artifact exports record the acting agent. Agent exports stay inside the server's artifact export root. v0.24.1 recorded these writes as owner or system actions and accepted agent export destinations outside that root.
- HTTP memory proposals, open loops, queue tasks, projects and brain charter writes apply the caller's sensitivity ceiling. The proposal CLI and legacy proposal and queue tools apply the same rule. v0.24.1 let admitted callers make these writes above their ceilings.
- Changing a source's stored sensitivity or a connector's default sensitivity requires the owner or an unbound `admin_agent` key. A trusted operator key can still review a readable source or save connector settings at the existing sensitivity. v0.24.1 let trusted operator keys make both sensitivity changes.

## Reads

PostgreSQL avoids repeated JIT compilation on scoped reads with a project-bound key and on `alice_resume` and `alice_context_pack` with an unbound `admin_agent` key. v0.24.1 turned JIT off on the workspace route and used the server default for those other requests.

## The web console and its checks

The web console updates Next.js and `eslint-config-next` from 16.4.1 to 16.4.5. The full web dependency check drops the `picomatch` exception after the withdrawal of GHSA-fc5q-39xc-vjpf on 2026-11-18. v0.24.1 listed that exception with an expiry of 2026-12-17. The PyPI package does not include the web console.

## Behaviour changes an integrator will notice

- `alice_lessons` returns `yours` when the keyed writer has a readable waiting lesson or a decision in the last seven days. The block includes `waiting`, `published_in_last_7_days` and `not_published_in_last_7_days`, with optional `not_published` entries containing `id`, `applies_when`, `reason` and `at`.
- A successful MCP lesson commit and a waiting review item can carry `similar`, with each result's match described in `why`. A waiting lesson's review list item also carries its `lesson` block. An empty `similar` list means no matches, while null means the matches were unavailable or were skipped for that list item.
- A caller without standing to read an unpublished lesson receives the missing-item answer on review or explain, and a hidden idempotent replay retains the conflict answer.

## Security

This release was checked with automated security scanning and internal adversarial review. A second internal review is still being worked through: the fixes this release carries are named below, and some of its findings are not fixed yet. No one outside the project has audited the code.

- Charter promotion changes and sensitivity reductions require review standing, which v0.24.1 did not require for admitted charter saves.
- Review standing protects candidate and private-only corrections, and a writer's pending confirmation is limited by its deadline. v0.24.1 did not apply these correction checks to waiting rows.
- Keyed operator writes identify the agent and keyed artifact exports stay under the server's export root. v0.24.1 could attribute these writes to the owner or system and allowed agent destinations outside the root.
- The applicable create and save surfaces enforce the key's sensitivity ceiling, which v0.24.1 did not enforce on those writes.
- The owner or an unbound admin key controls changes to stored source and connector default sensitivity, which v0.24.1 allowed trusted operator keys to change.
- Next.js 16.4.5 fixes seven advisories that apply to the web console in v0.24.1: GHSA-mfr8-8qww-v76h, GHSA-vc7v-qv4w-wrv8, GHSA-7qx7-33qx-rqx2, GHSA-f3mh-rxg3-f5g2, GHSA-pc58-hwjq-p385, GHSA-rhh4-g77r-r9qj and GHSA-vvgp-ww4w-46vf.

A security advisory for the correction change and the charter change is published with this release.

## What this release does not claim

- A lesson written before the first key keeps its standing after keys are issued. See the [known limitations](../alpha/known-limitations.md).
- A reader sees the writer and publishing agent ids, so choose neutral ids. See [shared lessons](../alpha/shared-lessons.md).
- `alice_lessons` reads a projection of readable published lessons, and its cost grows with that number. See the [lookup limits](../alpha/known-limitations.md).
