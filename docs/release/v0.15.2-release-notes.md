# Alice v0.15.2 Release Notes
<!-- alice-release-state: {"schema_version":"alice_release_document_state_v1","version":"0.15.2","publication_status":"published","checksums_status":"recorded"} -->

**The `/v1` API now requires an agent key, keyless callers are refused off
loopback, and importers stop following links out of the directory you chose.**

`v0.15.2` is a security release. Every deployment should take it, and operators
running `/v1` reachable from anything but loopback should take it now.

Read the `/v1` limitation below before you change any firewall rule. This
release adds authentication to `/v1`. It does not add authorization, and the
guidance to keep `/v1` loopback-only is unchanged.

## `/v1` requires an agent key

Before this release, `/v1` had no agent-key authentication of any kind. The
identity middleware returned early for every path that did not begin with
`/v0/`, so a caller who could route to the port could bootstrap a workspace,
register model providers pointing anywhere, and supersede memory objects
without presenting a credential. The only control in front of it was the
operator's firewall and the deployment guide's instruction to keep `/v1` local.

Once the bound user has provisioned an agent API key, every `/v1` request must
present it. While no key exists the surface stays keyless for local callers,
which keeps first-run setup working.

## Keyless requests fail closed away from loopback

The keyless allowance used to depend on how the server was bound, which meant a
deployment could reason itself into leaving it open. It is now unconditional: a
request that presents no key and does not come from a loopback client is
refused, whatever the bind address says.

## Importers stay inside the directory you point them at

Importers walked source trees with ordinary path helpers, which follow
directory symlinks and treat a link to a regular file as a regular file. One
link planted inside an import root could pull in bytes from anywhere the server
process could read.

Source listing no longer descends or accepts symlinks, each file is opened once
with the link check on the descriptor rather than the path, and the text that
gets parsed is the same text that gets archived as evidence, so the two cannot
diverge between passes. A source that is not a regular file, a FIFO for
instance, is refused instead of importing as an empty document.

Selection now runs on the directory listing rather than on files already read.
An unrelated `.json` neighbour is never opened, so one stray file with
undecodable bytes no longer fails an import that had no reason to look at it.
When a selected file genuinely cannot be decoded, the error names the file
instead of reporting a byte offset with no path.

## Dependency advisories fixed rather than excepted

Two advisories published after `v0.15.1` affected the web toolchain:
`GHSA-rgw5-rvv9-x895` in brace-expansion, which explicitly bypasses the
mitigation an earlier exception relied on, and `GHSA-5p4m-2wfm-xmqj` in
js-yaml.

The standing exception existed because no patched release existed inside the
affected major lines, and the only route forward broke eslint and the coverage
provider. Maintainers have since backported within each line, so each is pinned
to its own patched release and no major moves. The exception is deleted rather
than left to expire, because an exception that outlives its reason is how the
next finding gets buried. Both audits now pass with zero exceptions in force.

## Compatibility

No database migration. No schema change.

A deployment with no agent key provisioned is unchanged on loopback. Once a key
exists, `/v1` callers must send it, and the repository's own example agents and
phase11/phase14 smoke scripts do not yet do so. They are unpackaged and are not
loaded by any deployment, but they will return 401 against a keyed installation
until the follow-up lands. The server log names the header to add.

Import file matching is now case-insensitive on extensions, so a directory
holding an unrelated `.JSON` or `.MD` file that was previously ignored is now
considered. Any failure is loud and names the file.

## How this was verified

An external review of the release branch reported four P1 blockers. All four
mechanisms reproduced against a live database. All four were then downgraded,
because the review graded them without measuring the baseline: two reproduce
identically on `v0.15.1` and predate this work, and the `/v1` authorization gap
described below is an incomplete new control rather than a regression, since
this release permits nothing that the published release refused.

> **Correction (2026-10-04):** the review of the release branch named in this section was not an audit of the code. This project's security checks are automated security scanning and internal adversarial review, findings triaged and fixed. No one outside the project has audited the code.

The finding that did stand was ours: a middleware docstring claimed the
resolved key was the actor for the request. Nothing read the resolved identity
and no row recorded an agent, so the claim was false and has been corrected
rather than softened.

Selection behaviour was measured across a 63-layout matrix run against the
published release, the branch, and the fix. No layout exists in which an import
that previously succeeded now imports less.

Suite 4,541 unit tests passed with 2 skipped, and 408 integration tests passed.
Both new regression tests were checked by reverting each fix and confirming
they fail.

## Known limitations

- **`/v1` authenticates but does not authorize.** Every `/v1` request must
  present a valid key, and it does not matter which one. A key minted as
  `read_only_agent` can bootstrap a workspace, register providers, and
  supersede memory over `/v1` exactly as an administrative key can. Permission
  profiles are enforced on `/v0/vnext`, on the MCP tool surface, and in the
  CLI, and are not enforced on `/v1`. Treat every agent key as full privilege
  until this closes.
- **`/v1` writes are not attributed.** No row written through `/v1` records
  which key made it, so a quarantine sweep by agent key cannot reach them.
  Revoking a compromised key leaves manual review by timestamp as the recourse.
- **Keep `/v1` off the public network.** The deployment guide's instruction is
  unchanged and remains correct, for the two reasons above. The reverse proxy
  allowlist still excludes `/v1` and the deployment smoke check still fails a
  configuration that exposes it.
- **Importers still trust the directory you choose.** A local actor with write
  access inside a selected import root can still reach content outside it, by
  hard link, which is indistinguishable from ordinary content at this layer, or
  by swapping an ancestor directory for a symlink between listing and read.
  Both are present in `v0.15.1` and both require local write access to a folder
  you selected. Point importers only at directories you control.
- **Archived import evidence is decoded text, not a byte image.** The read
  applies universal newlines, so a CRLF source archives as LF. The archive
  matches what the parser consumed, which is the property that matters for
  evidence, but it will not checksum against the original file.
