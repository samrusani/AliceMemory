# Alice v0.10.0 Release Notes
<!-- alice-release-state: {"schema_version":"alice_release_document_state_v1","version":"0.10.0","publication_status":"pending","checksums_status":"pending"} -->

> **Correction (2026-09-27):** the audits and review passes named in these notes were internal adversarial review, not an independent or external audit.

`v0.10.0` is a security, reliability, and quality release. It remediates every
finding from the third external audit of `v0.9.4` — fixed at the class level
rather than per-reproduction — and clears the accumulated P2 backlog. The
withdrawn `v0.9.3` candidate was never published; `v0.9.4` was published but
carried partial remediations and a backfill regression, both corrected here.

## Correctness fixes (third-audit findings)

- **One signed-vector write contract.** The eval seeder and both embedding
  backfill paths (CLI and SQLite onramp) now persist the full v2 signature —
  provider, model, endpoint fingerprint, content digest, and version — through
  a single helper, so seeded and backfilled vectors are retrievable by
  production search. This corrects the v0.9.4 backfill regression that wrote
  vectors retrieval could never match.
- **Scoped, atomic capture dedupe.** Candidate/assertion deduplication is now
  aware of project scope, lifecycle status, domain, and sensitivity, and is
  enforced atomically by a partial unique index (migration `0085`). Identical
  text in a different project, a restatement after rejection, or a different
  classification is no longer silently dropped.
- **Complete hard filters.** People/time scope predicates are pushed into the
  store query before `LIMIT`, per-person entity edges are resolved in bulk (no
  200-edge cap), and the query embedding is computed once per request, so valid
  scoped rows are no longer lost behind a bounded post-filter scan.
- **Fail-closed lifecycle graph.** The supersession cycle guard rejects
  pre-existing cycles and dangling pointers, not only new cycles; migration
  `0086` repairs databases carrying three or more stale duplicate pointers.
  Migration `0084` is unchanged from `v0.9.4`.
- **Truthful rollup totals.** Roll-up cards report their authoritative member
  count and disclose display truncation separately, instead of publishing the
  truncated display count as the total.
- **Honest release gate.** The canonical eval measures vector participation from
  actual signed candidates and fails closed on skipped or partially-skipped
  suites; the per-user supersession advisory lock is acquired before row locks.

## Quality and hardening (P2 backlog)

`pgvector 0.8+` is enforced at install/migration/doctor; import/backup closes a
validate/import race and bounds memory; the web app is decomposed with
real-browser, accessibility, coverage, and bundle-budget gates and zero
TypeScript errors; first-party Python mypy is clean; the packaged README uses
portable links; and release publication now requires a structured, exact-SHA
control attestation plus a protected signed-vector semantic report.

## Upgrade

`alembic upgrade head` applies migrations `0085` and `0086` (idempotent; safe
downgrades). After upgrade, run `alicebot vnext memories backfill-embeddings` to
re-embed existing vectors under the correctly-signed v2 signature; unlike
`v0.9.4` these vectors are now retrievable. No other operator action is required.

## Verifying this release

Alice publishes to PyPI through GitHub Trusted Publishing. Once published, the
wheel and source distribution carry PyPI's integrity attestations, which bind
each file to this repository, the release tag, the publishing workflow, the
exact commit, the release event, and the protected `pypi` environment —
verifiable on the project's PyPI page. Their exact SHA-256 digests will be
recorded in `docs/release/v0.10.0-checksums.txt` in this repository as part of
the post-publication commit.
