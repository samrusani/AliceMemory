# Alice v0.15.7 Release Notes
<!-- alice-release-state: {"schema_version":"alice_release_document_state_v1","version":"0.15.7","publication_status":"published","checksums_status":"recorded"} -->

**Take this release if you import notes. `v0.15.6` stopped flattening
`raw_text` and then returned none of the stored document.**

There is no schema change, no migration, and no configuration change.

## Imported documents are readable

`v0.15.6` fixed flattening so capture stored the document you pointed at.
Retrieval still threw that document away.

`alice_context_pack` packed sources as bibliography entries with no text, and
`alice_recall` searched memories only. Capture writes candidates, and
candidates are unsearchable as memories by design, so the natural sequence
(import, then recall) answered `count=0` for content the store held.

Three independent causes, each sufficient on its own:

1. The packed source carried `metadata_json`, which capture fills with the
   entire document. `estimate_item_tokens` JSON-dumps the item to price it, so
   a 235KB source was charged roughly 59k tokens against a 50k ceiling, was
   rejected, and latched the truncation flag so every later section was
   dropped too.
2. MCP compaction emitted six fields and none of them was text.
3. `alice_recall` never looked at sources.

Packed sources now carry an excerpt of the chunk retrieval already ranked
best, windowed around its best-matching line and labelled
`excerpt_kind: imported_source_material`. `alice_recall` returns the same
under a separate `sources` key. `results` are facts Alice asserts. `sources`
are material the user imported and the agent may read and quote.

Nothing here promotes a candidate or makes one searchable as a memory. The
promotion gate is unchanged. `count=0` on memories after capture is still
the design.

Verified on a copy of a 226-document vault over stdio MCP, against a local
build. The live store was not touched.

```
before   sources=0   truncated=True    no text
after    sources=1   truncated=False   excerpt carries the quote
```

Sources that reached the pack through the provenance or title/recency lists
had no ranked chunk and arrived empty. They now get a bounded fallback
excerpt. Line scoring ignores link-only navigation (`## Related` wikilinks,
ordered lists, embeds). The excerpt window keeps the line it was selected
for, including when that line sits at the end of the chunk. Trimming no
longer collapses on text without spaces.

`alice_recall`'s source excerpts apply the same project, people and time
fence as `alice_context_pack`. Source scope is an exclusion filter. The
parameter is required with no default.

## An oversized list no longer flattens into word-count slices

`_split_large_part` only sees paragraphs that alone exceed the chunk budget,
and it was doing `part.split()` then rejoining with spaces. A numbered or
bulleted list written one item per line, with no blank line between items,
was stored as flattened word-count slices with individual items cut in half.

Found in a real 226-document vault import on `v0.15.6`: of 710 chunks, five
carried no newline and two sat at the ceiling, one ending mid-sentence
inside item 22 of a quote list.

An oversized paragraph now splits on its own lines before falling back to
words. An oversized single line is word-split on its own, so one long item
no longer flattens its neighbours. Already-captured content is not
re-chunked.

## Resume and recent decisions apply the policy fence

`alice_resume` and `alice_recent_decisions` already computed a full policy
decision and then applied only the project part, or less. A public-only
caller, and a request that narrowed `project_scope` without a bound
identity, still received a private other-project decision.

Both helpers now take `effective_domains`, `effective_sensitivity_allowed`,
and `effective_project_scope` as required kwargs with no default. Resume no
longer uses the unscoped `list_events` shortcut.

Left alone on purpose, same class, not default tools:
`alice_recent_changes`, `alice_resume_debug`,
`alice_vnext_recent_memory_commits`, and `alice_project_dashboard`.

## Re-import

If you imported notes on `v0.15.6`, **upgrade is enough for readability.**
Excerpts are a read-path change. The chunks were already stored.

If you imported on `v0.15.5` or earlier, **delete those candidates and
import again.** `v0.15.6` fixed flattening; this release does not rewrite
those rows.

If you need the new list-splitting boundaries, re-capture those documents.
There is no re-chunk migration.

## What this release does not claim

The LongMemEval 81.2% figure is a `v0.12.0` harness number from a
privileged `store_chunks` path that no MCP tool offers. This release does
not restate it as a product-path measurement. `ALICE_LME_EXCERPT_SOURCE`
lets the harness measure the pack instead. The default is unchanged.

## Known limitations

Unchanged from `v0.15.6`:

- **`/v1` authenticates but does not authorize.** Keep it loopback-only.
- **Importers trust the directory you point them at.**
- **Archived import evidence is decoded text, not a byte image.** CRLF
  sources archive as LF.
- **Tool failures return a generic code and no detail.** The server reports
  `tool_not_found`, `tool_request_failed`, or `tool_execution_failed`. The
  message does not say why.

Known and deliberately not fixed here:

- **`alice_vnext_ingest_agent_output` still collapses whitespace in
  `content`.** Legacy surface only (`ALICE_MCP_LEGACY_TOOLS=1`). It does
  not reach the chunker.
- **An indented `#` line is treated as a heading by the chunker.**
  CommonMark would read a four-space-indented `#` as code.
- **Four read paths still compute a policy decision and do not fully apply
  it:** `alice_recent_changes`, `alice_resume_debug`,
  `alice_vnext_recent_memory_commits`, and `alice_project_dashboard`. None
  of them is a default tool.
