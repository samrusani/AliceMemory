# Alice v0.18.0 Release Notes
<!-- alice-release-state: {"schema_version":"alice_release_document_state_v1","version":"0.18.0","publication_status":"pending","checksums_status":"pending"} -->

**Take this release if you capture notes or import files into Alice, use
Hermes or OpenCode, or run on SQLite and want to import markdown or ChatGPT
exports.**

- v0.17.0 had no credential check on source capture. `alice_capture`,
  `alicebot vnext sources capture-text` and the connectors stored a note that
  holds a token, and `alice_recall` and `alice-memory brief` return it.
- v0.17.0 `alice_resume` and `alice_recent_decisions` showed candidate
  memories. A captured line that read like a decision came back as the last
  decision before anyone reviewed it.
- The v0.17.0 markdown folder import followed a symlink out of the folder,
  and the ChatGPT import stored any JSON file.
- On v0.17.0, Hermes turn capture saved nothing. Every turn got HTTP 422 and
  the plugin dropped it.
- v0.17.0 install printed the whole command of an `alice` entry it did not
  write, including a token in it. A `--data-dir` holding a newline added
  lines to the receipt.
- OpenCode is a new opt-in install host. On SQLite, `alice-memory
  import-markdown` and `alice-memory import-chatgpt` are new.

## What to do after upgrading

1. **Upgrade.** With pip: `pip install -U alice-memory==0.18.0`. With uv,
   run `uvx alice-memory@0.18.0 --version` once; it prints the version the
   hosts get. Restart the hosts afterwards.
2. **Find stored sources that hold credential material.** Earlier versions
   stored them as written, and upgrading does not change them.
   `alice_recall` and `alice-memory brief` still return that text.
   - **SQLite:** run `alice-memory doctor` (add `--data-dir` if your vault is
     not `~/.alice`). Two lines are new:

     ```text
     flagged sources: 2
     flagged source ids: e0d4d1c4-..., ffd56fad-...
     ```

     Doctor exits 0 either way. No command deletes a source on SQLite, and
     `alice-memory export` and `import` carry flagged sources across
     unchanged. Rotate each credential a flagged source holds.
   - **Postgres:** run `alicebot vnext doctor`. The new `flagged_sources`
     check lists the ids in `details.source_ids`, with the message
     "Delete each listed source with delete_source." Delete each one with
     `DELETE /v0/vnext/sources/{source_id}`; no `alicebot` command deletes a
     source. Run the doctor again: the check passes with a count of 0. The
     check is a warning, not a blocking failure. Rotate the credentials too.
3. **Hermes:** if you set `sync_turn_capture_enabled: true`, or set
   `bridge_mode` to `assist` or `auto` yourself, turn capture now saves
   memories. On v0.17.0 it saved nothing. To keep it off, set
   `sync_turn_capture_enabled: false`. Turn capture uses the legacy `/v0`
   routes, so the server must run in development or test mode, or with
   `LEGACY_V0_ENABLED_OUTSIDE_DEV` set and a loopback client. Otherwise the
   plugin gets HTTP 404 and drops the turn, as on v0.17.0.
4. **OpenCode:** run `alice-memory install --host opencode`, then check the
   file with `opencode debug config` and `opencode mcp list`. If you added
   Alice by hand on v0.17.0, read "OpenCode host" first: install refuses an
   `alice` entry it did not write.
5. **SQLite imports:** use `alice-memory import-markdown --from PATH` and
   `alice-memory import-chatgpt --from PATH`. The `alicebot vnext sources`
   imports need Postgres and now say so.

## OpenCode host

`alice-memory install --host opencode` writes `mcp.alice` into OpenCode's
global config. OpenCode is opt-in: the default hosts are still Claude
Desktop, Claude Code, Cursor and OpenClaw. v0.17.0 refused `--host opencode`
with `invalid_request` and exit 2.

A new file is `~/.config/opencode/opencode.json`, with `$schema` and this
entry. There is no `environment` key:

```json
{
  "type": "local",
  "command": ["uvx", "alice-memory", "mcp", "--data-dir", "<data dir>"]
}
```

The target is the file that already holds `mcp.alice`. Otherwise it is
`opencode.jsonc` when that file exists, else `opencode.json`. A 0-byte
`opencode.jsonc` is skipped. Each rewrite is backed up into
`<data dir>/backups/host-configs/` first.

- **`opencode.json` in strict JSON:** a re-run keeps `timeout`, `enabled`,
  `cwd`, `environment` and sibling servers.
- **`opencode.jsonc`**, and an `opencode.json` that is not strict JSON, are
  edited as text. The receipt says `format: jsonc, edited as text`.
  Comments, sibling servers and every other byte stay. An `alice` entry
  there that holds a key install does not carry, such as `timeout`, is
  refused with its line number. Edit that entry by hand.
- **Refused, exit 1 with `install_refused`:** `alice` in more than one file
  or under `mcp.servers`, an `alice` entry install did not write, and a
  legacy `opencode/config` file. Nothing is written for OpenCode.
- **An OpenCode directory install cannot read** fails that host with
  `install_failed`. Other hosts in the same run are still written.

There is no SessionStart hook for OpenCode. The receipt says
`session_start: none` and suggests `alice-memory brief`. A dry run prints
copied values such as `environment.ALICE_AGENT_API_KEY` as `<hidden>`.

The Real host CI workflow now also installs pinned OpenCode 1.18.32 and
checks that OpenCode reads the written file and rejects a broken entry. The
pinned run passed 5 of 5 tests on the last pull request in this release. The
weekly canary runs the same tests on the latest OpenCode.

## Capture safety

**Credential check on every capture path.** `alice_capture`,
`alicebot vnext sources capture-text` and `capture-file`, the connectors,
and both vNext imports refuse a source that carries credential material in
its title, author, URI, path, external id, text or metadata keys. Nothing is
written. A connector batch counts the refusal as skipped, not failed.
v0.17.0 stored the source.

**Resume shows only active memories.** `alice_resume` (its last decision and
its next action) and `alice_recent_decisions` read only active memories. A
captured `Decision:` or `Commitment:` line is a candidate. It stays in review
until you approve it. In v0.17.0 both tools returned candidates. The session
brief and `alice-memory brief` did not show candidates in v0.17.0 either.

**Folder import stays in the folder.** The vNext markdown import refuses a
folder that holds a symlinked or non-regular file, and writes nothing. A
single markdown file is now accepted. v0.17.0 followed the symlink and
stored the file it pointed to, and refused a single file.

**A JSON file that is not a chat export is refused.** A ChatGPT import with
no conversations fails with "ChatGPT export has no conversations" and writes
nothing. v0.17.0 stored the file's text as a source.

## Importing on SQLite

Two new commands write sources and chunks to the SQLite vault, where MCP
recall reads them:

```bash
alice-memory import-markdown --from PATH
alice-memory import-chatgpt --from PATH
```

For markdown, PATH is a file or a folder. Both take `--data-dir` or `--db`,
`--domain` and `--sensitivity`, and print a JSON receipt.

- **No candidates.** A `Decision:` line is stored as source text. No memory
  row is created.
- **Line filter.** A line that holds credential material, or a private key
  block, is stored as `[withheld: credential material]`. A BEGIN line with no
  END is withheld through the end of the file. A ChatGPT message that holds
  one is stored as the same placeholder, and a conversation title that holds
  one is stored as `withheld`. The rest is imported.
- **Receipt.** `skipped_credentials` counts credential skips.
  `skipped_credential_items` names each one as `line N`, `lines N to M`,
  `conversation X message N` or `file K (name withheld)`, never the text.
  `skipped_count` counts whole files skipped. A second run of the same file
  has status `duplicate`.
- **A token in a file name** skips that file only.
- **Refused, exit 1 with `import_path`, nothing written:** a token in the
  folder name ("The import folder name is withheld"), one file that is not
  valid UTF-8 (the error names the file), a symlinked file, a JSON file with
  no conversations, and a path that does not exist.

`alicebot vnext sources import-markdown` and `import-chatgpt` with a SQLite
URL exit 2 with `sqlite_import_use_alice_memory` and name the two commands
above. v0.17.0 exited 1 with `invalid_request`.

## Install receipts

- **Control characters are escaped** in every receipt value. A newline
  prints as `\u000a`, so a `--data-dir` holding a newline cannot add a
  receipt line. v0.17.0 printed the newline.
- **A foreign `alice` entry is named by its program only.** When install
  refuses an `alice` entry it did not write, the reason says
  `its command is node` for `/usr/local/bin/node`, and `Program` for
  `C:\Program Files\nodejs\node.exe`. A command containing `://` is
  `a URL`. A command that carries credential material is
  `a command that looks like a credential`. v0.17.0 printed the whole
  command string, including a token in a later word.
- **A token glued to a URL is hidden.** In "alice-memory mcp would not start
  with the args ..." reasons and in dry-run snippets, a word that still
  carries credential material after URL masking prints as `<hidden>`.
  v0.17.0 hid only the part after the scheme, so the token before it
  showed.

## Credential floor

- **Keys are read with their values** in provenance, in legacy admission
  `value`, and in the `value` column that `alice-memory import` restores. A
  secret name over an opaque value, such as `{"api_key": "..."}`, is now
  refused there. v0.17.0 read these by value only and accepted it. A backup
  holding such a row now stops at `import_credential_material`.
- **`rollup_key` at import** is exempt only in the shape the product writes,
  `[scope:<16 hex>:]topic:|entity:|semantic:<label>`, in `metadata_json` or at
  `value.rollup.rollup_key`. The label is still read by value. Rollup cards
  the product made still restore. v0.17.0 exempted any `rollup_key` value.
  Now an opaque value, or one with a 64-hex scope, is refused.
- **A routing `session_key`** such as `agent:main:telegram:dm:12345` is an
  identifier and is accepted where keys are read. The v0.17.0 floor read it
  as a secret name and refused it. An uppercase profile, or an opaque tail
  such as a Slack `C04...` id, is still refused.
- `gpg_key` over a key id is refused and `signingkey` over a key id is
  accepted, as in v0.17.0.

## Hermes and the continuity capture routes

**Header-only writes reach the route.** A JSON `POST` under `/v0` that sends
`user_id` only in `X-AliceBot-User-Id` now reaches the handler. On v0.17.0,
`/v0/continuity/captures/candidates`, `/captures/commit` and `/captures`
answered 422 for a missing `body.user_id`. That is how the Hermes plugin
calls them, so it dropped every turn. A body `user_id` that differs from the
authenticated user still gets 401. With legacy `/v0` off outside development
and test, these routes still return 404.

**Auto-save takes only user-role explicit prefixes.** In `assist` and `auto`
mode, a candidate is auto-saved only when it comes from the user and matches
an explicit prefix such as `decision:`. A regex hit, and any candidate from
the assistant, is queued for review. From either role, v0.17.0 auto-saved an
explicit candidate of an allowed type at confidence 0.9 or more in `assist`,
and any allowed type at 0.85 or more in `auto`.

**Credential check on the captures routes.** `POST /v0/continuity/captures`
refuses text that carries credential material with 400 `invalid_request`,
and stores nothing. On v0.17.0, a client that sent `user_id` in the body got
201, and the raw text was stored in the capture inbox. When a candidate from
the assistant reply carries a credential, the commit for that turn returns
400 and nothing from the turn is kept, including a valid user decision.

`sync_turn_capture_enabled` lives in the Hermes plugin config. Its default
did not change.

## Blocked idempotent replay

A blocked agent that replays `POST /v0/vnext/memories/commit` gets 403
"agent policy blocked this action" only when the stored domain, sensitivity
and project scope all equal the request's. Any other difference, including a
stored row that was relabelled since, gets the same 400 `invalid_request` a
trusted writer gets for its own conflict, with no labels in the body. The
policy rows are kept. v0.17.0 answered every one of these cases with HTTP
500 and rolled the policy rows back.

MCP `alice_memory_commit` keeps the rows and answers `tool_request_failed`.
v0.17.0 answered `tool_execution_failed` and rolled them back. A new commit
that policy rejects still returns 200 with status `rejected`.

## Behaviour changes an integrator will notice

- **`alice_capture` refusal.** A capture that carries credential material
  answers `isError: true` with `tool_request_failed` and no detail. v0.17.0
  answered `status: imported`. `alicebot vnext sources capture-text` exits 1
  with `invalid_request` (v0.17.0: exit 0).
- **Fewer resume results.** `alice_resume` `last_decision` and `next_action`
  and `alice_recent_decisions` no longer return candidates.
- **Import refusals.** The vNext markdown import refuses symlinked and
  non-regular files and accepts a single file. The ChatGPT import refuses a
  file with no conversations. `alice-memory import` refuses a memory row
  whose `value` holds a secret name over an opaque value, or whose
  `rollup_key` is not in the product's shape.
- **Doctor output.** `alice-memory doctor` prints two more lines at the end,
  `flagged sources:` and `flagged source ids:`. The ids line is empty when
  nothing is flagged. `alicebot vnext doctor` has a new `flagged_sources`
  check.
- **Receipts.** Control characters in receipt values print as `\uXXXX`.
  Refusal reasons for foreign entries name only the program.
- **HTTP status.** `POST /v0/continuity/captures` with credential material:
  400 (v0.17.0: 201 with a body `user_id`). Header-only `/v0` JSON writes:
  the handler runs (v0.17.0: 422). A blocked idempotent replay: 403 or 400
  (v0.17.0: 500).
- **`--host opencode`** is accepted by `alice-memory install`.

## Schema and migration

There is no schema change: no new Alembic revision, no SQLite table or
column change, and no new runtime dependency. A v0.17.0 SQLite vault opens on
v0.18.0 as it is. Upgrading does not rewrite stored rows. A source that an
earlier version stored with a credential stays until you remove it; see step
2.

## What this release does not claim

This release was checked with automated security scanning and internal
adversarial review, findings triaged and fixed.

The credential check is a pattern check. It misses some formats and refuses
some harmless notes. `docs/memory/promotion-personas.md` lists the gaps. It
checks new writes only: it does not clean stored sources, and reads do not
filter them. The checks do not all agree. A low-entropy key shaped like an
AWS access key id is refused by the continuity routes but accepted by source
capture, and the doctor does not flag it.

Instruction-shaped notes are not refused. No catch rate against instruction
attacks has been measured.

OpenCode was run against the written file only in CI, on Linux, at 1.18.32
and at the latest release. No other version or platform was run.

## Known limitations

Unchanged from v0.17.0:

- **Install exits 0 when it finds no launcher.** It warns, and writes
  entries that run `uvx`.
- **A refusal reaches an MCP client as `tool_request_failed`,** with no
  detail. This now includes a refused `alice_capture`.

New in this release:

- **No command removes a stored source on SQLite.** Doctor lists flagged
  sources and exits 0.
- **Receipt items name the line, not the file.** In a folder import,
  `line 2` does not say which file it is in.
- **A withheld ChatGPT conversation title is not counted** in
  `skipped_credentials` or `skipped_credential_items`.
- **`POST /v0/continuity/captures/candidates` has no credential check.** It
  echoes a token back in the candidates. The commit that follows refuses it,
  so nothing is stored.
- **The commit route trusts the role a client sends.** A candidate labelled
  as a user explicit prefix is auto-saved. The Hermes plugin sends the
  server's own candidates.
- **One credential in the assistant reply drops the whole Hermes turn.**
- **Every capture refusal is a generic `invalid_request`.** A client cannot
  tell a credential refusal from another bad request.
- **OpenCode has no SessionStart hook.** Run `alice-memory brief` instead.
