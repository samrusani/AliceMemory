# Alice v0.10.4 Release Notes
<!-- alice-release-state: {"schema_version":"alice_release_document_state_v1","version":"0.10.4","publication_status":"published","checksums_status":"recorded"} -->

> **Correction (2026-09-27):** the audits and review passes named in these notes were internal adversarial review, not an independent or external audit.

`v0.10.4` is a correctness and truthfulness release. It remediates the fifth
external audit's confirmed findings on the published `v0.10.3` baseline — five
P1s, one downgraded provider defect, and the full triaged P2 set — plus the
independent-review correction passes that followed. `v0.10.3` itself remains
sound and published; nothing in this release invalidates its artifacts or
provenance.

## Correctness

- **Hosted settings are workspace-explicit.** All 23 hosted Telegram channel
  operations accept an explicit workspace selection, the Settings panel sends
  its entered workspace on every request, and channel resolution no longer
  mutates the session workspace, so outcomes are order-independent and an
  operator can never inspect one workspace while mutating another.
- **Project-update review is coherent on every surface.** A shared locked
  dispatcher classifies generic artifact reviews for HTTP, MCP, and CLI; the
  queue service itself rejects direct project-update lifecycle changes.
  Pending review validates the candidate's status, type, workflow, digest,
  project, and scope, and rejects every durable supersession representation
  before mutating anything. Terminal accepted/rejected replay is proven from
  the locked artifact plus exactly one append-only review revision and exactly
  one coupled decision event — counted before validation, so contradictory or
  fabricated evidence fails closed with zero mutation. Reviewer attribution
  (human, agent, CLI) flows into events and revisions.
- **Explicit empty project scope is authoritative in SQLite.** One
  presence-aware resolver and one backend-stable identity now govern Python,
  SQLite, and PostgreSQL across policy and key admission, capture dedupe,
  retrieval, scheduler, connectors, consolidation, and rollups. An explicit
  `project_scope: []` is preserved through database reopen and is invisible to
  every project filter; stale legacy aliases can no longer resurrect it.
  Project identity is a deduplicated, code-point-sorted set: ASCII identifiers
  compare case-insensitively, non-ASCII identifiers compare exactly, and only
  the six ASCII whitespace characters normalize.
- **Persisted-source scope follows the complete source envelope.** Source and
  parent-chunk search, retrieval admission, Brain, Projects, Connections,
  Contradictions, and artifact-trace authorization resolve canonical scope by
  key presence through the full envelope precedence on both stores.
- **Resume answers the query it was asked.** `alice_resume` filters open-loop
  rows and their events before limits in both stores using one deterministic
  contract: ASCII case-insensitive literal substring on row fields and each
  recursive event string leaf, exact non-ASCII, literal `%`, `_`, and `\`,
  and string-only `next_action` metadata.
- **No-auth providers invoke correctly.** OpenAI-compatible invocation carries
  `auth_mode` and omits the Authorization header for `none`; the internal
  sentinel can never reach the wire.
- **Deterministic embedding compare-and-swap.** PostgreSQL computes the signed
  embedding content digest with the exact CPython 3.12 whitespace table used
  by Python and migration `0090` instead of the locale-dependent POSIX class,
  eliminating NBSP-class and control-character disagreement and the re-embed
  loop it could cause.

## API and documentation truth

- **Runtime-true OpenAPI.** All 294 operations carry contracts derived from
  actual handler envelopes: 49 exact, 243 closed source-derived, and two
  genuinely polymorphic operations with individual reasons. Phantom wrapper
  keys are gone, and a registry gate fails closed on drift. This prospectively
  corrects the v0.10.3 release notes' overbroad claim that all 294 operations
  were source-verified; the immutable v0.10.3 record is not rewritten.
- **Evergreen package metadata.** The PyPI description now comes from a
  publication-neutral document instead of tag-time README prose, and release
  checks verify the built wheel and sdist metadata contain no version-state
  language, so the PyPI page can no longer go stale by construction.
- **Truthful product copy.** Hosted onboarding describes its instruction-only
  scope, navigation includes every shipped view, the landing page reports the
  real view count and data modes, and the admin rate-limit metric uses the
  exact overview count.

## Reliability and scale

- Task, artifact, memory, and trace pages issue independent requests in
  parallel with per-leg provenance instead of serial waterfalls.
- Source capture validates the resolved envelope on every dedupe path and
  rotates stale dedupe keys atomically; collisions fail closed.
- Key-bound MCP explanation authorizes every expanded memory, source, entity,
  and continuity object before returning evidence.
- Configured API base-path prefixes are preserved by the web client.

## Upgrade

`alembic upgrade head` applies migration `0090` (project-scope identity and
source-dedupe repair; idempotent, online-safe, tested downgrade). Migrations
`0084`–`0089` are unchanged. Two previously shipped migration scripts are
corrected in place for databases that have not yet run them: `0083` now treats
every present canonical `project_scope` key as authoritative (including empty)
and normalizes whitespace deterministically, and `0088` pins its fingerprint
backfill to an immutable v1 helper with a golden digest.

**Migration `0083` caveat — read before upgrading an existing database.** If
your database already ran migration `0083` under v0.10.2 or v0.10.3, memories
that carried an explicit empty `project_scope` may have had that intent
irreversibly overwritten. v0.10.4 corrects the migration for databases that
have not yet run it and repairs source dedupe identity via migration `0090`,
but affected memory rows require manual resolution against a pre-upgrade
backup or capture audit evidence (see the migration preflight guidance in
`RELEASING.md` and the v0.10.4 handoff records). Fresh installs and upgrades
from `0082` or earlier are unaffected. This release does not and cannot
reconstruct lost scope intent automatically.

**Ingest contract change.** Connectors now persist an absent incoming project
scope as a present, authoritative empty scope on agent identity and artifact
metadata, so legacy `project_id` values in incoming item metadata no longer
scope proposed memories implicitly.
