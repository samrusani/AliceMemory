# Alice v0.22.0 Release Notes
<!-- alice-release-state: {"schema_version":"alice_release_document_state_v1","version":"0.22.0","publication_status":"published","checksums_status":"recorded"} -->

**Take this release if you run the PostgreSQL stack and an agent posts to
`POST /v0/vnext/agents/ingest-output`, or if you keep a SQLite vault and want to try
ranking the passages of your notes with embedding vectors. The route now refuses a request that
its agent policy blocks, with the same HTTP 403 as `POST /v0/vnext/sources`, and writes
nothing for it. v0.21.1 and earlier wrote a source and an artifact for that request.
The vectors are an opt-in and are off by default, and no gain from them has been
measured, so this release does not claim better retrieval. There is no tool and no
migration. See "What to do after upgrading".**

- v0.21.1 answers HTTP 201 and writes a source, a `needs_review` artifact and, with
  `propose_memory`, a candidate memory when the agent policy blocks an agent output.
  v0.22.0 answers HTTP 403 and writes none of them.
- v0.21.1 answers HTTP 500 when the title, the content or a source ref of an agent
  output holds credential material. v0.22.0 answers HTTP 400 and writes nothing.
- v0.21.1 embeds memories and the recall query when you configure an embeddings endpoint,
  and never the chunks of an imported or captured note. v0.22.0 can embed those chunks,
  only when `ALICE_SOURCE_EMBEDDINGS=on` and only to an endpoint on this machine, and
  `ALICE_SEARCH_QUALITY=vectors` then ranks passages with them. In v0.21.1 that value
  makes `alice_recall` answer `tool_request_failed`.

## What to do after upgrading

1. **Upgrade the copy your hosts run** (`uv tool upgrade alice-memory`, or
   `pip install -U alice-memory` in the environment they use), check it with
   `alice-memory --version`, and restart your hosts.
2. **No migration.** PostgreSQL stays at revision `20261011_0097`. A SQLite vault that
   v0.21.1 wrote opens in v0.22.0 and needs no step. A vault that never turns
   `ALICE_SOURCE_EMBEDDINGS` on is unchanged, gets no new table and still opens in
   v0.21.1. Step 6 covers a vault that holds chunk vectors.
3. **PostgreSQL stack: check what posts to the agent output route.** A request that the
   agent policy blocks now gets HTTP 403 and writes nothing. That covers a
   `read_only_agent` key, a `memory_proposal_agent` key, a key whose domains exclude
   the requested domain, and a call with no key that declares no
   `permission_profile` and names an `agent_id` other than `hermes` and `openclaw`,
   which is held as a read-only agent. If an integration of the last kind should write,
   send it with a key, or declare a `permission_profile` that may write
   (`trusted_local_agent` or `admin_agent`). A call that declares `read_only_agent` is
   refused.
4. **Rows v0.21.1 wrote for a blocked request stay.** The source holds the blocked
   decision in `metadata_json.policy_decision`, its artifact is `needs_review`, and
   `propose_memory` left a candidate memory. v0.21.1 wrote them for requests the policy
   had refused, so check them before you rely on them.
5. **To try the vectors**, point `ALICE_EMBEDDINGS_BASE_URL` and `ALICE_EMBEDDINGS_MODEL`
   at an embeddings endpoint on this machine and set `ALICE_SOURCE_EMBEDDINGS=on`. New
   imports and captures embed their chunks. Run `alice-memory reindex-embeddings --sources`
   for notes you imported earlier, then set `ALICE_SEARCH_QUALITY=vectors` to rank with
   them. To stop, unset `ALICE_SEARCH_QUALITY` (or set `passage`) so recall stops using the
   vectors, unset `ALICE_SOURCE_EMBEDDINGS` so no more text is sent, and run
   `alice-memory reindex-embeddings --sources --drop` to delete every chunk vector and the
   table.
6. **To go back to v0.21.1 after you used the vectors**, run
   `alice-memory reindex-embeddings --sources --drop` first. v0.21.1 opens a vault that
   holds chunk vectors, but its `alice-memory export` fails on it until they are dropped.
7. **Claude Code plugin.** The marketplace file on `main` pins the v0.21.1 tag commit
   until a change after this release moves it, so a marketplace install runs v0.21.1
   code until then.

## The agent output route

`POST /v0/vnext/agents/ingest-output` asks the agent policy for a decision on the action
`source.capture` before it writes. In v0.21.1 and earlier the route handed that decision
to the connector service even when it was `blocked`. The service recorded it in the
metadata of the source and wrote the source, its chunk and a `needs_review` artifact
anyway, plus a provenance link and, with `propose_memory`, a candidate memory. The caller
got HTTP 201 with the blocked decision in the body. `POST /v0/vnext/sources` answered the
same key and labels with HTTP 403.

v0.22.0 answers a blocked request as `POST /v0/vnext/sources` does: HTTP 403, the detail
`agent policy blocked this action` and the policy decision. It writes no source, chunk,
artifact, provenance link or memory for it. It still stores the policy events of the
refusal and records the agent identity, as any request does. The connector service
refuses a blocked decision as well, so a caller that hands it one gets the refusal and no
rows.

The route answers HTTP 400 with `vNext agent output ingest request is invalid` when the
title, the content or a source ref holds credential material. The answer repeats none of
the request and nothing is written. v0.21.1 answered HTTP 500.

Not changed: the MCP tool `alice_vnext_ingest_agent_output` and the command
`alicebot vnext agents ingest-output` already refused a blocked decision and wrote
nothing. A `trusted_local_agent` key, and a call with no key that names `hermes` or
`openclaw` or declares `trusted_local_agent` or `admin_agent`, still write a source, a
`needs_review` artifact and a provenance link, and a candidate memory when
`propose_memory` is set. A sensitivity above the labels of a key that may write does not
block the request on its own: the decision is `allowed_with_filtering` and the route
writes, as in v0.21.1. A SQLite vault is not affected: the route needs the PostgreSQL
stack, and `alice-memory` serves no HTTP API. A test now reads every route that asks the
agent policy for a decision and fails when one does not act on a blocked decision.

## Passage vectors, an opt-in

v0.22.0 can embed the chunks of the notes you import or capture and rank passages with
the vectors. Both are off by default, both are for the SQLite vault, and nothing in this
release shows that they retrieve better. No measurement of them is published.

**Embedding the chunks.** With `ALICE_SOURCE_EMBEDDINGS=on`, `alice-memory import-markdown`,
`alice-memory import-chatgpt` and `alice_capture` send the chunks they save to the
embeddings endpoint after they commit, and `alice-memory reindex-embeddings --sources`
embeds the chunks that have no current vector. Setting `ALICE_EMBEDDINGS_BASE_URL` and
`ALICE_EMBEDDINGS_MODEL` alone still embeds memories only, and the values `1`, `true` and
`yes` leave the opt-in off.

**Only to this machine.** The chunks go only to an endpoint on this machine: `localhost`,
a name under `.localhost`, an IPv4 address in `127.0.0.0/8` written as four decimal
numbers, or `::1`, with no proxy of the environment that would carry the request. For any
other endpoint, `127.1` and an endpoint behind a proxy included, nothing is sent and the
chunks stay pending as `endpoint_not_on_this_machine`, in the receipts and in
`alice-memory doctor`. Remote endpoints are not supported for source embeddings in this
release. Memory embeddings are unchanged and still work with any endpoint.

**What is sent.** For each chunk, the document prefix of the model (`search_document: ` for
nomic-embed-text), the source title, the headings above the chunk and the chunk. Not sent:
a chunk the credential check flags, a chunk of links or headings only, a chunk with fewer
than 32 readable characters, and anything on a `--dry-run`. The labels of a source decide
nothing about what goes to an endpoint on this machine, so the chunks of a confidential
note are sent too.

**Where the vectors live.** In a new SQLite table, `source_chunk_embeddings`, made when the
first vector is stored, at the width the model gives. Export leaves the vectors out and
says how many the vault holds, and the import receipt says the chunks arrived without
them. `alice-memory sources delete`, `sources prune` and `import-markdown --supersede`
delete the vectors of the source they retire, and `reindex-embeddings --sources --drop`
deletes every vector and the table and sends nothing. A vault keeps at most 250,000
vectors by default (`ALICE_SOURCE_EMBEDDINGS_MAX_VECTORS`).

**Ranking with the vectors.** `ALICE_SEARCH_QUALITY=vectors` runs passage mode with the
vectors of the chunks. It needs `ALICE_SOURCE_EMBEDDINGS=on`, an embeddings endpoint and
chunks embedded with the same model. Without any of them, and on PostgreSQL, `alice_recall`
answers as `passage` does and `debug` says why. Each recall embeds its query once, with the
query prefix of the model and a two second timeout, and after a failure the stage pauses for
30 seconds. Inside every document it shows, the chunks are ranked by the fusion of their
rank by words and their rank by vector, and a third of the head of the result is held for
documents that only the vectors found. A caller whose key has limits is ranked from the
vectors of the sources it may read and of no others. Unset, `passage` and `off` rank as they
did, and nothing reads the vectors unless `vectors` is set.

**Cost.** With `vectors` set, one more request on each recall, and about 3 KB of memory for
each chunk vector of 768 numbers once the first recall has loaded them. The copy in memory is
limited to 512 MB by default (`ALICE_SOURCE_VECTOR_CACHE_MAX_MB`), and past the limit the stage
is skipped and says so. The page
[Embeddings of source chunks](../alpha/mcp-tools.md#embeddings-of-source-chunks) has the
rules, the other limits and the cost in full.

## Other changes in the package

- `alice-memory doctor` prints five lines about source embeddings on every SQLite vault,
  `source embeddings: off` included.
- The SQLite source reads share one predicate for which sources a caller may read, and
  the vector stage uses it too. It changes no result.
- Two comments in `credential_floor.py` and `legacy_credential_check.py` were reworded.
  The credential check is otherwise unchanged.
- The bench scripts (`scripts/alice_bench.py` and `scripts/showcase_bench.py` now run
  `--search-quality vectors`), the scripted walkthrough (`scripts/showcase_walkthrough.py`)
  and the web console (a topic box for what changed on the continuity page, the `undici`
  and `zod` pins of its test and lint tooling, and the removed exception for a withdrawn
  `braces` advisory) are not part of the PyPI package. A wheel and a source distribution
  built from the tree hold no file from `scripts/` or `apps/web`.

## Behaviour changes an integrator will notice

- `POST /v0/vnext/agents/ingest-output` answers HTTP 403 with the decision for a blocked
  request, where v0.21.1 answered HTTP 201. That includes a call with no key that names an
  agent and declares no profile. It answers HTTP 400 for credential material, where v0.21.1
  answered HTTP 500.
- The receipts of `alice-memory import-markdown`, `alice-memory import-chatgpt` and
  `alice_capture` gain a `chunk_embeddings` object only when the opt-in is on. The
  receipts of `sources delete`, `sources prune` and `import-markdown --supersede` count
  `chunk_vectors`, and the `retained_data` of the first two says that a vector can be
  turned back into much of its text.
- `alice-memory export` prints a note when the vault holds chunk vectors, and
  `alice-memory import` prints one when chunks arrive without them.
- `alice-memory reindex-embeddings` takes `--sources` and `--drop`. There are five new
  settings: `ALICE_SOURCE_EMBEDDINGS`, `ALICE_SOURCE_EMBEDDINGS_MAX_VECTORS`,
  `ALICE_SOURCE_VECTOR_CACHE_MAX_MB`, `ALICE_SOURCE_VECTOR_SCOPED_CACHE_MAX_MB` and
  `ALICE_SOURCE_VECTOR_SCOPED_COPIES`, and `ALICE_SEARCH_QUALITY` takes the value `vectors`.
- No tool is added or removed: the default surface lists 3 tools, the full surface 12, and
  the legacy flags bring it to 74 and 77. The recall of a vault that sets none of the new
  settings returns what it returned.

## Security

This release was checked with automated security scanning and internal adversarial
review, findings triaged and fixed. No one outside the project has audited the code.

The change a security-minded reader will care about is the agent output route. In v0.21.1
and earlier a key that the agent policy had refused (a read-only or proposal-only key, or a
key whose domains exclude the requested domain) could still store a source, a
`needs_review` artifact and a candidate memory through `POST /v0/vnext/agents/ingest-output`.
v0.22.0 refuses the request. Advisory identifier: pending.

The other change that touches trust is the vectors. With the opt-in on, the text of your
notes goes to your embeddings endpoint and each recall sends its query there. The connected
address has to be loopback before a byte is written, so a name that resolves elsewhere gets
nothing. A vector can be turned back into much of the text it was made from, so the vectors
of a source are deleted with it.

## What this release does not claim

It does not claim that the vectors retrieve better. No measurement of them is published,
and the opt-in changes what `alice_recall` returns only when `ALICE_SEARCH_QUALITY=vectors`
is set. It does not claim that remote embeddings endpoints work for source text: they are
not supported. It does not claim that a deleted vector is gone from the disk: the
write-ahead log, unused space in the vault file and earlier backups can keep vector bytes
until a checkpoint and `VACUUM`. It does not claim that nothing reaches the endpoint after a
scrub: a scrub committed after the text of a chunk was chosen can still be followed by that
text reaching the endpoint on this machine, and the vector that comes back is not stored. It
does not remove the rows that v0.21.1 wrote for blocked agent output requests. It does not
claim that any other route wrote for a blocked decision: the others already refused, and this
release adds a test that keeps it so.
