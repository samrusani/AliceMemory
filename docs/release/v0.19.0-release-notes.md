# Alice v0.19.0 Release Notes
<!-- alice-release-state: {"schema_version":"alice_release_document_state_v1","version":"0.19.0","publication_status":"published","checksums_status":"recorded"} -->

**Take this release if you use Codex or Claude Code, if your host caps the
size of the session brief, or if you keep comments in a Hermes config.**

- v0.18.0 has no `--host codex`. A Codex user adds the MCP entry and the
  SessionStart hook by hand.
- v0.18.0 has no Claude Code plugin. The plugin needs a marketplace file
  that a change after the v0.19.0 tag adds, so until that lands
  `alice-memory install --host claude-code` is the way in.
- The v0.18.0 session brief drops a note that does not fit its 4,000 token
  budget, can run past 15,000 characters, and makes the hook print `{}`
  when the newest fact, an open loop or a source title is long: more than
  about 990 distinct words in any vault, or, with a captured source in the
  vault, more than about 50,000 bytes. v0.19.0 fixes both. See "Session
  brief".
- The v0.18.0 brief prints a superseded fact, and a captured sentence that
  was corrected later, as if they were current.
- v0.18.0 accepts a relative `--data-dir`. The MCP server and the hook then
  create a vault under whatever directory the host started them in.
- v0.18.0 MCP tools declare no hints.
- On Hermes, a v0.18.0 re-run of install drops a comment inside the `alice`
  block.

## What to do after upgrading

1. **Upgrade.** With pip: `pip install -U alice-memory==0.19.0`. With uv,
   run `uvx alice-memory@0.19.0 --version` once; it prints the version the
   hosts get. Restart the hosts afterwards.
2. **Codex:** run `alice-memory install --host codex`. Codex is opt-in, and
   any `--host` replaces the default set, so this writes Codex only. Open
   Codex and trust the `alice-memory-session-start` hook at "Hooks need
   review" or with `/hooks`. Until you do, Codex skips it without a
   message. Check the MCP entry with `codex mcp get alice`. If your
   `config.toml` already defines hooks, install writes the MCP entry, prints
   the hook, and exits 1 with `install_hook_by_hand`. Add the printed hook to
   `config.toml`, trust it, and run install again: it says `unchanged in
   config.toml` and exits 0.
3. **Claude Code:** keep using `alice-memory install --host claude-code`.
   The plugin cannot be installed from the v0.19.0 tag alone, because its
   marketplace file arrives in a change after the tag. When it does, use the
   plugin or install, not both. If both exist, install refuses with exit 1
   and `install_refused_plugin`, and the plugin's brief starts with a line
   saying Alice is set up twice. To keep the plugin, run `claude mcp remove
   alice --scope user` and remove the `alice-memory-session-start` hook from
   `~/.claude/settings.json`.
4. **Data directory:** look at every host config that passes `--data-dir` to
   `alice-memory mcp`. A value that is empty, or not absolute after `~`
   expansion, now stops the server with exit 2 and `data_dir_invalid`. That
   includes the literal text `${HOME}/.alice`, which a host that does not
   expand it hands over as is. The check does not cover
   `ALICE_MEMORY_DATA_DIR`, which only the session-start hook reads: if a
   host sets it, give it an absolute path.
5. **Hermes:** if you keep comments inside the `alice` block of
   `~/.hermes/config.yaml`, a re-run that has nothing to change now leaves the
   file alone. A re-run that has to change the block refuses, prints the
   block, and leaves the file and its comments as they are.
6. **Scripts that read import receipts:** a folder import now names the file
   in each `skipped_credential_items` entry, for example `file 1 (week.md)
   line 2`. See "Import receipts and capture".

## Codex host

`alice-memory install --host codex` writes the `alice` MCP entry into Codex's
`config.toml`. With `--home`, that is `<home>/.codex/config.toml`. Without it,
install uses `CODEX_HOME` when set, and a `CODEX_HOME` that is not an absolute
path is refused. The default hosts are still Claude Desktop, Claude Code,
Cursor and OpenClaw. v0.18.0 refuses `--host codex` with `invalid_request` and
exit 2.

A new file holds only Alice's table. There is no `env` table, and the data dir
is in `args`:

```toml
[mcp_servers.alice]
command = "uvx"
args = ["alice-memory", "mcp", "--data-dir", "<data dir>"]
```

- **Edited as text.** Every byte outside Alice's `command` and `args` stays.
  A re-run keeps `enabled = false` (the receipt says Codex will not start
  alice), `startup_timeout_sec`, and any `[mcp_servers.alice.tools.<tool>]`
  table Codex wrote when you remembered an approval. The written file has
  mode `0600`.
- **Refused, exit 1 with `install_refused`, file untouched:** a comment
  inside `command`, `args` or an inline `env`; a key install does not carry,
  such as `cwd`, `url` or `enabled_tools`; and the value checks listed in
  `docs/integrations/codex.md`. The receipt prints a snippet to add by hand.
- **The receipt ends with** `next: check it with: codex mcp get alice`.

### SessionStart hook

The same command also writes a SessionStart hook to `<CODEX_HOME>/hooks.json`,
so a new Codex session starts with the session brief in front of the model.
Install appends one group at the end of `hooks.SessionStart`. It never inserts
ahead of yours, because Codex keys its trust records by index. The handler is:

```json
{
  "type": "command",
  "command": "uvx --from alice-memory alice-memory-session-start --data-dir <data dir> --format markdown",
  "timeout": 120,
  "additionalContextLimit": 0
}
```

- **Markdown, not JSON.** Codex rejects the JSON that Cursor and Claude Code
  read. The Real host CI test `test_real_codex_ignores_json_hook_output` runs
  that case against Codex.
- **`additionalContextLimit` is `0`,** so Codex never spills the brief to a
  file. The brief has its own cap, described below.
- **Trust is yours.** Install never writes `trusted_hash`. The receipt says
  `session_start: written to hooks.json, not trusted yet` and prints the step:
  choose Review hooks at "Hooks need review", or use `/hooks`. A re-run that
  changes the command, a new `--data-dir` for example, adds this line:
  `The hook changed, so Codex will skip it until you trust it again.`
  A re-run that changes nothing says `session_start: unchanged in hooks.json`
  in its receipt.
- **A new MCP entry follows the hook's vault.** Without `--data-dir`, install
  opens the data dir of an Alice hook that is already installed, so the entry
  and the hook use one vault.
- **Refused, nothing written:** a `hooks.json` Codex would skip, such as a
  handler with a type Codex does not read. The reason starts `Codex would skip
  this hooks.json`. Codex skips a whole file on one type error, your own
  groups included.
- **`config.toml` already defines hooks.** Codex would load both files and run
  the brief twice, so install writes no hook. It writes the MCP entry, prints
  the hook as TOML, and exits 1 with `install_hook_by_hand` until the hook is
  in `config.toml`. `install_hook_by_hand` is a new error code. It is used
  only when install wrote the MCP entry and refused only the hook. Every
  other refusal keeps `install_refused`.

`docs/integrations/codex.md` has the full rules for carried keys, config
layers, Windows quoting and the `hooks.json` checks.

## Claude Code plugin

`plugins/alice-memory` is a Claude Code plugin: an MCP server and a
SessionStart brief on one SQLite file. Its `plugin.json` version is 0.19.0,
and both commands pin `alice-memory==0.19.0`:

- the server runs `uvx --from alice-memory==0.19.0 alice-memory mcp --data-dir
  ${user_config.data_dir}`;
- the hook runs `uvx --from alice-memory==0.19.0 alice-memory-session-start`.

The plugin needs `uv` on `PATH`. It has one option, `data_dir`, with the
default `~/.alice`. Use the same folder as your other hosts.

- **The hook reads the option itself.** Its command has no `--data-dir`,
  because Claude Code does not run a hook whose arguments reference a plugin
  option that is not set. When `CLAUDE_PLUGIN_ROOT` is set and non-empty and
  no `--data-dir` is given, `alice-memory-session-start` reads
  `CLAUDE_PLUGIN_OPTION_DATA_DIR`, else `~/.alice`, and ignores
  `ALICE_MEMORY_DATA_DIR`. The hook and the server open one vault. A
  relative option value makes the hook print one line asking for an absolute
  path, exit 0, and open nothing. Outside the plugin the hook reads
  `--data-dir`, then `ALICE_MEMORY_DATA_DIR`, then `~/.alice`, as in v0.18.0.
- **Plugin and install exclude each other.** `alice-memory install --host
  claude-code` skips, with exit 0, when the `alice-memory@alicememory` key
  under `enabledPlugins` in `~/.claude/settings.json` is true and install has
  not written its own Claude Code entries. It refuses when both exist. When
  the key is false, install writes and notes that enabling the plugin later
  sets Alice up twice. Project and local plugin scopes are invisible to
  install.
- **The hook warns when both exist.** When the plugin's hook finds install's
  `alice` entry in `~/.claude.json`, or install's hook in
  `~/.claude/settings.json`, the brief starts with `Alice is set up twice in
  Claude Code.` and the commands that remove install's entries. A file it
  cannot read or parse does not stop the brief.
- **The marketplace file is not in the v0.19.0 tag.** This repository has no
  `.claude-plugin/marketplace.json` at the tag. A change after the tag adds
  it, with marketplace name `alicememory` and one plugin entry whose source is
  pinned to the tag's commit. The plugin id is `alice-memory@alicememory`.
  The Real host CI marketplace check runs `claude plugin marketplace add .` in
  a checkout that holds the file, then `claude plugin install
  alice-memory@alicememory`. `--config data_dir=<absolute path>` sets the
  option at install. The plugin README says Claude Code does not auto-update a
  third-party marketplace, and gives `claude plugin update
  alice-memory@alicememory` for updating.

## Session brief

The brief is what SessionStart injects and `alice-memory brief` prints. It
changes for Claude Code's size cap and for facts that were replaced.

- **A long note is cut, not dropped.** When a note's brief line, label and
  quotes included, would pass 1,500 characters, the note is cut to the
  longest part that fits with the marker, so the line stays at or under
  1,500. The cut ends on the last word boundary, or on a grapheme boundary
  when there is no word break or the word boundary would keep less than 60
  percent of what fits. The marker sits outside the quote:
  `**fact** (cut; N characters stored): "..."`. N is the stored note's length in UTF-16 code
  units. A line that does not fit the room left is skipped, and later short
  facts, open loops and sources still fit. In v0.18.0 a note that did not fit
  the token budget was dropped, and a vault whose only note was that long
  printed `Nothing stored yet.`
- **The brief has a character cap.** It is counted in UTF-16 code units and
  is at most 9,499 minus the `reserve` the caller passes, which is the
  length of the caller's own prefix line. The hook's final cap drops whole
  trailing lines and never cuts inside one. `alice-memory doctor` prints
  `last brief: N / 9500 characters`, where v0.18.0 printed a token estimate
  out of 4,000 tokens. In v0.18.0 a brief could run past 15,000 characters.
  `plugins/alice-memory/README.md` gives 10,000 characters as Claude Code's
  cap on hook output, over which Claude Code injects a file path and a short
  preview.
- **A long fact no longer empties the brief.** The brief searches sources
  with a string it builds from an explicit query, the newest fact, an open
  loop or a source title. SQLite refused that search in two cases in
  v0.18.0, and the hook printed `{}` and `alice-memory brief` exited 1 for
  both. A string over about 50,000 bytes raised a pattern error, `LIKE or
  GLOB pattern too complex`, when the vault held a source. A string with
  more than about 990 distinct search terms (ASCII words of two or more
  characters that are not stopwords) raised `Expression tree is too large`,
  in any vault. That is roughly 30,000 bytes of ordinary prose, less when
  the words are rare, or 3,000 bytes of two-character tokens. In v0.19.0 the
  brief uses the string as it is when it is at most 40,000 bytes, at most
  40,000 bytes after case folding, and has at most 499 distinct search
  terms, so an ordinary brief is unchanged. Otherwise it keeps a few hundred
  characters of the string's tokens. The facts and loops still print, and so
  do the sources whose words match. A repeated word counts once.
  `alice_recall` and `alice_context_pack` are not changed. See "Known
  limitations".
- **Current facts only.** A memory whose `superseded_by` is set, or whose
  status is `superseded`, is left out. A `**source**` line is left out when
  the captured sentence's `quoted_from` memory was corrected or superseded
  after the capture. When the older row is still active and carries
  `superseded_by`, `alice_recall` still returns it after the current one,
  with `validity.superseded: true`. A row that a correction moved to
  `superseded` is not returned by recall at all. Recall's source excerpt for
  a corrected memory carries `derived_memory_corrected: true` and
  `current_memory_id`, and `alice_context_pack` marks the excerpt the same
  way.
  The stored chunk and the quote are unchanged. In v0.18.0 the brief printed
  the old sentence as a `**fact**` or a `**source**` line, and recall did not
  mark the excerpt.

The cut can still split a few kinds of character: Devanagari conjuncts, Thai
and Lao SARA AM, and Prepend characters. Tag-sequence flags and Hangul jamo
stay whole.

## MCP tool hints

Every MCP tool sets `openWorldHint` to false. Alice is local by default.
`alice_recall` and `alice_context_pack` can call an embedding endpoint you
configure with `ALICE_EMBEDDINGS_BASE_URL`. That endpoint is outside Alice,
so the hint describes Alice and not that service.

- `readOnlyHint` is true on `alice_recall`, `alice_resume`,
  `alice_context_pack`, `alice_recent_decisions` and `alice_explain`. None of
  them changes a memory or a source. `alice_context_pack` records one event
  log row of type `retrieval.context_pack_compiled`, and an agent identity
  row can be recorded too. Neither is a state change the client asked for.
- `destructiveHint` is false on `alice_memory_commit` and `alice_capture`,
  which only add.
- `destructiveHint` is true on `alice_memory_review`, `alice_memory_correct`,
  `alice_memory_manage` and `alice_open_loops`. `alice_memory_review` only
  lists review items or shows one, and changes no memory or source. With an
  agent identity it records the same event log and identity rows as the
  read-only tools. Its flag is conservative: it is grouped with the tools
  that act on the review queue, and Codex's default rule asks before it
  runs.

The hints go out in `tools/list` for the three default tools and for all
eleven core tools with `ALICE_MCP_FULL_TOOLS=1`. The 65 legacy tool
definitions carry `openWorldHint: false` too. The rule they follow is
Codex's default approval rule as the code records it: a tool that declares
`readOnlyHint`, or `destructiveHint` false together with `openWorldHint`
false, runs without a prompt. v0.18.0 tools declare no hints. No test here
drives a Codex approval prompt.

## Data directory checks

`alice-memory mcp` refuses a `--data-dir` that is empty or not absolute after
`~` expansion. It names the value and exits 2 with `data_dir_invalid`.
`alice-memory-session-start` refuses a non-empty `--data-dir` value, or a
Claude Code plugin `data_dir` option value, that is not absolute after
expansion: it prints `Alice: the data directory "<value>" is not an
absolute path; set an absolute path.` and exits 0. The refusal does not
cover `ALICE_MEMORY_DATA_DIR`. An empty session-start value still falls back
to that variable, then `~/.alice`, and a relative value in the variable is
not checked: the hook creates the vault under the current directory. Only
the hook reads the variable. The MCPB manifest's default `${HOME}/.alice` is
refused when a host passes it unexpanded. v0.18.0 accepted a relative value,
and the literal `${HOME}/.alice`, and created the vault under the current
directory.

## Hermes install

`alice-memory install --host hermes` leaves `~/.hermes/config.yaml` alone,
comments included, when the `alice` block with its comments removed already
matches what install would write. The receipt says `action: unchanged`. When a
change is needed and the block holds a full-line or inline comment, install
refuses with exit 1 and `install_refused`, writes no backup, prints the block,
and does not change the file. In v0.18.0 the re-run rewrote the block and
dropped the comment.

## Import receipts and capture

- **Folder receipts name the file.** An item reads `file 1 (week.md) line 2`
  or `file 1 (week.md) lines 3 to 5`. A flagged file name still shows as `file
  K (name withheld)`. v0.18.0 printed only `line 2`.
- **A flagged ChatGPT title is counted.** A conversation title that holds a
  token is stored as `withheld` and counted in `skipped_credentials` and
  `skipped_credential_items` as `conversation X title`. v0.18.0 stored
  `withheld` and did not count it.
- **The line filter and capture use the commit door's verdict.** A markdown
  line, a ChatGPT message, title or id, and a captured source are checked
  with it. A low-entropy key shaped like an AWS access key id, which the
  credential floor alone leaves alone, is now withheld by both imports and
  refused by `alice_capture`. The same verdict also withholds other shapes
  the floor alone lets through, such as a numeric password written in a
  sentence, so re-importing a notes folder can skip a line that v0.18.0
  imported. `alice-memory doctor` flags a stored source that holds the key.
  In v0.18.0 the line filter imported that line, capture stored it, and the
  doctor did not flag it, so a source stored by v0.18.0 is flagged after
  the upgrade.
- **Candidate capture withholds a token.** `POST
  /v0/continuity/captures/candidates` and `alice_capture_candidates` return
  the placeholder instead of the token in `normalized_text` and
  `evidence_snippet`, and store nothing. Committing that placeholder, through
  `POST /v0/continuity/captures/commit` or `alice_commit_captures`, is refused
  the way a credential is, with HTTP 400 on the route, and stores nothing.
  v0.18.0 echoed the token in the response.
- **The Postgres doctor names the route.** The `flagged_sources` check says
  `Delete each listed source with DELETE /v0/vnext/sources/{id}.` v0.18.0 said
  `delete_source`, which is a store method and not a route.

## Install dry run

A dry run of `alice-memory install` now shows booleans and numbers on the top
level of your existing entry as they are. This applies to every JSON host:
Claude Desktop, Claude Code, Cursor, OpenClaw and OpenCode. For OpenCode that
includes `"enabled": false` and `"retries": 3`. A string value from your entry,
and every value under `environment`, `env`, `headers` or any other map, stays
`<hidden>`, whatever its type. In v0.18.0 a dry run showed only `command`,
`type`, `timeout` and `cwd` from the top level and printed every other value
as `<hidden>`.

## Behaviour changes an integrator will notice

- **Install.** `--host codex` is accepted. Three exit-1 error codes now
  separate refusals: `install_refused`, `install_refused_plugin` (the plugin
  is enabled and install's Claude Code entries exist) and
  `install_hook_by_hand` (Codex, hook only). v0.18.0 has the first only.
- **MCP.** `tools/list` carries `annotations` on every tool. v0.18.0 carried
  none.
- **Session brief.** At most 9,499 UTF-16 code units. Long notes are cut with
  a `(cut; N characters stored)` marker. Superseded facts and stale source
  lines are left out. The doctor line is `N / 9500 characters`.
- **Servers and hooks.** A relative or empty `--data-dir` stops `alice-memory
  mcp` with exit 2. The session-start hook prints one line and exits 0.
- **Install dry run.** Booleans and numbers on the top level of your existing
  entry print as they are, on every JSON host. In v0.18.0 they printed as
  `<hidden>`.
- **Import receipts.** Folder items carry the file name. A flagged ChatGPT
  title is counted.
- **Recall.** A source excerpt can carry `derived_memory_corrected` and
  `current_memory_id`. A superseded row carries `validity.superseded: true`.
- **Capture.** `alice_capture` refuses a low-entropy AWS-shaped key. Candidate
  responses hold a placeholder where a token was. A folder re-import can skip
  a line that v0.18.0 imported.

## Schema and migration

There is no schema change: no new Alembic revision, no SQLite table or column
change, and no new runtime dependency. A v0.18.0 SQLite vault opens on v0.19.0
as it is. Upgrading does not rewrite stored rows. A source that an earlier
version stored with a credential stays until you remove it. Run `alice-memory
doctor` on SQLite, or `alicebot vnext doctor` on Postgres, to list those
sources.

## What this release does not claim

This release was checked with automated security scanning and internal
adversarial review, findings triaged and fixed.

The credential check is a pattern check. It misses some formats and refuses
some harmless notes. `docs/memory/promotion-personas.md` lists the gaps. It
checks new writes only: it does not clean stored sources, and reads do not
filter them. The checks do not all agree. The memory commit door, source
capture, the Markdown and ChatGPT imports and the SQLite source doctor use
the commit door's verdict. Backup export and import, and memory approvals,
review edits and corrections, among others, use the credential floor alone;
`docs/memory/promotion-personas.md` lists the rest. A low-entropy
key shaped like an AWS access key id is therefore refused by the first group
and accepted by the second: `alice_memory_correct` can store it as an active
fact, the session brief prints it, `alice-memory export` lists no offender,
and `alice-memory import` restores it. The doctor reads sources only, so it
does not flag such a fact. v0.18.0 behaves the same way at those doors.

> Correction, 2026-09-30. The sentence above says backup import uses the
> credential floor, and reads as if import checked what it restores. It checks
> memory rows for credential material. Sources, chunks, revisions, loops,
> entities and event rows come across unchanged, in v0.19.0 and v0.18.0, and a
> token in one of them is stored and can be returned by recall and the session
> brief. The v0.19.0 doctor reads source rows and `raw_text`, not chunk text, so
> a token that sits only in a chunk prints `flagged sources: 0`. On main, import
> lists any such record on its receipt and the doctor reads chunk text.

Instruction-shaped notes are not refused. No catch rate against instruction
attacks has been measured.

Codex and Claude Code were run against what install and the plugin write only
in CI, on Linux, at the pinned versions (codex-cli 0.158.0 and claude 2.1.281).
The weekly canary is set up to run the same tests at the latest release, and
it has not run the Codex or plugin tests yet. No other version or platform
was run. The Codex hook was run through `codex exec` against a loopback mock,
not a real model.

## Known limitations

Unchanged from v0.18.0:

- **Install exits 0 when it finds no launcher.** It warns, and writes
  entries that run `uvx`.
- **A refusal reaches an MCP client as `tool_request_failed`,** with no
  detail. This includes a refused `alice_capture`.
- **No command removes a stored source on SQLite.** Doctor lists flagged
  sources and exits 0.
- **The commit route trusts the role a client sends.** A candidate labelled
  as a user explicit prefix is auto-saved.
- **One credential in the assistant reply drops the whole Hermes turn.**
- **Every capture refusal is a generic `invalid_request`.** A client cannot
  tell a credential refusal from another bad request.
- **OpenCode has no SessionStart hook.** Run `alice-memory brief` instead.
- **The credential checks do not all agree.** See "What this release does not
  claim".
- **`alice_recall` and `alice_context_pack` return a tool error for a query
  with about 991 or more distinct search terms.** A search term is an ASCII
  word of two or more characters that is not a stopword, and a repeated word
  counts once. SQLite raises `Expression tree is too large`, and an MCP client
  gets `tool_execution_failed` with the message `The tool could not be
  executed`. That is roughly 30,000 bytes of ordinary prose. The session
  brief bounds such a string in this release, and these two tools do not.
  v0.18.0 fails the same way. With a captured source in the vault, a query
  over about 50,000 bytes also returns that error (SQLite `LIKE or GLOB
  pattern too complex`), in both versions. Keep the query short.
- **A long `alice_recall` query can be slow.** This release does not bound it.

New in this release:

- **Codex skips the hook until you trust it,** and skips it again each time a
  re-run changes its command. Install cannot trust it for you.
- **A `config.toml` that already defines hooks gets no hook from install.**
  It prints the hook and exits 1 until you add it.
- **Install checks Alice's Codex entry and the number ranges in
  `docs/integrations/codex.md`.** It does not check every rule Codex applies
  to the rest of the file.
- **No test drives a Codex approval prompt.** The tool hints follow Codex's
  default rule as recorded in this repo, and that rule is Codex's to change.
- **The marketplace file is not in the tag,** so the plugin cannot be added
  from the tag alone. Project and local plugin scopes are invisible to
  install, and the plugin needs `uv` on `PATH`.
- **A Hermes `alice` block with a comment is edited by hand** whenever install
  has a change to make.
- **The brief cut can split some characters,** as listed under "Session
  brief".
- **A relative `ALICE_MEMORY_DATA_DIR` is not checked.** The data directory
  checks cover `--data-dir` and the Claude Code plugin's `data_dir` option.
  The session-start hook still creates a vault under the current directory
  for a relative value in that variable, including the literal text
  `${HOME}/.alice`. Set it to an absolute path.

## Install

```bash
pip install alice-memory==0.19.0 && alice-memory install
```

With uv: `uvx alice-memory install`. The pip path needs Python 3.12 or later.
