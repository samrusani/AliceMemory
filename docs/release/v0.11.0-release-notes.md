# Alice v0.11.0 Release Notes

`v0.11.0` is an unpublished release candidate. Preparing this document does
not authorize a tag, package upload, or GitHub Release.

> **Correction (2026-10-04):** v0.11.0 was published on 2026-07-15. The sentence above describes the state when these notes were drafted.

## Periphery cut

- The default runtime is narrowed to Alice's agent interface and
  retrieval/memory-quality product: the eleven core MCP tools, core HTTP and
  CLI workflows, per-agent keys, provenance, continuity, retrieval, traces,
  entities, artifacts, provider-backed embeddings, and the local review
  console.
- Telegram channels/polling/delivery, the hosted administration/design-partner layer, hosted
  identity/session/device management, chief-of-staff/chat/model-pack features,
  and the public `/v0/responses` chat surface are removed from the current
  product surface. The low-level response-generation/job machinery remains an
  internal durability layer for retained `/v1/runtime/invoke`.
- The allowlist-aware endpoint for ingesting an operator-supplied Telegram raw
  update remains a source-import contract. It does not poll Telegram, own a bot
  token, schedule delivery, or mount a channel product.
- Task, approval, execution, Gmail, and Calendar compatibility surfaces are
  disabled at mount time by default. A keyless local operator may temporarily
  enable them with `ALICE_LEGACY_SURFACES=1`; this compatibility flag is
  read at process import/start, so changing it requires restarting affected
  API, worker, and web processes. The flag is deprecated and scheduled for
  removal before `1.0`.
- Legacy MCP tools whose backing services were removed no longer exist. The
  retained long-tail memory tools require `ALICE_MCP_LEGACY_TOOLS=1`; exactly
  `alice_task_brief`, `alice_task_brief_show`, and
  `alice_task_brief_compare` additionally require
  `ALICE_LEGACY_SURFACES=1`. All legacy tools remain unavailable to key-bound
  servers.
- Existing database migrations and historical tables are retained as immutable
  schema history. Removed product surfaces do not mount or write those tables
  by default; no destructive migration is part of this cut.
- Production startup still validates local identity, role-separated database
  URLs, and CORS deployment settings, but no longer requires `S3_ACCESS_KEY` or
  `S3_SECRET_KEY`. No S3 client survives the periphery cut, and `/healthz` no
  longer echoes the dormant S3 endpoint setting.

## Upgrade notes

- Provider configurations created under hosted-era workspace identities are
  not adopted by the deterministic local workspace. Those rows are orphaned
  from the retained provider API after upgrade; bootstrap the local workspace
  and re-register providers before invoking them.
- `ALICE_LEGACY_SURFACES` cannot be changed in a running process. Restart each
  affected API, worker, and web process after changing the flag.

## Documentation and release truth

- The architecture, product brief, roadmap, current-state mirror, and active
  sprint packet now describe the same local-first agent-memory boundary as the
  runtime.
- Historical repair-batch ledgers moved out of the live roadmap/current-state
  documents into the handoff history index.
- The v0.10.4 Batch-16 truth receipt is treated as durable historical evidence
  rather than a presence-activated pin on all future production trees.
- Connector documentation now distinguishes ingestion of text extracted by an
  external OCR or transcription tool from OCR/transcription execution. Alice
  does not ship either execution capability.
- OpenAPI closure remains fail-closed against the post-cut operation registry;
  phantom operation keys and undocumented mounted routes still fail the gate.

## Release boundary

`v0.10.4` remains the latest published release until the transactional release
workflow publishes and verifies the exact `v0.11.0` candidate artifacts. Its
tag, release notes, checksums, and published files are unchanged.
