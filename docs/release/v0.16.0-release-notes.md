# Alice v0.16.0 Release Notes
<!-- alice-release-state: {"schema_version":"alice_release_document_state_v1","version":"0.16.0","publication_status":"published","checksums_status":"recorded"} -->

**Take this release if you want the README path from PyPI.** `v0.15.7`
can import a note and return it as a source. It cannot run
`alice-memory install` or `alice-memory demo --vault`.

There is no schema change and no migration. Nothing here promotes a
candidate or makes one searchable as a memory. `count=0` on memories
after capture is still the design.

## The default loop is on the wheel

`alice-memory install` writes Claude Desktop, Claude Code, Cursor, and
OpenClaw host config and prints the OpenClaw add line. Claude Code and
Cursor get a SessionStart hook:

```
uvx --from alice-memory alice-memory-session-start --data-dir <same as MCP>
```

Hermes is `--host hermes`. A `.mcpb` manifest is generated only when
you pass `--write-mcpb`.

`alice-memory demo --vault PATH` imports a markdown folder into a local
SQLite vault, then prints the import counts, a capture receipt when a
new source was saved, the doctor census, the session brief, and the one
`**source**` snippet a new session will quote. `--data-dir` defaults to
`~/.alice-demo`, not `~/.alice`. The command does not auto-promote and
does not open a review UI.

`alice-memory doctor` prints the local census: db path, source count,
searchable chunk count, committed fact count (`active` / `accepted`),
the last brief token estimate, and candidates waiting last. Every COUNT
binds `user_id`.

`alice-memory brief` prints labelled markdown (`**fact**`, `**source**`,
`**open loop**`). `alice-memory-session-start` wraps that for Cursor
`sessionStart` and Claude Code `SessionStart`, and fails open.

The default MCP handshake is three tools: `alice_memory_commit`,
`alice_recall`, `alice_resume`. The other eight core tools stay defined
and become listed and callable when `ALICE_MCP_FULL_TOOLS=1`. Hidden
core tools raise `MCPToolNotFoundError` and name that flag. Tool JSON
schemas are unchanged.

Capture and commit return a one-line `receipt`. A successful capture
with searchable chunks says `saved as source, N chunks searchable now`.
A zero-chunk success says `saved as source`. When candidates exist, the
line adds `M candidates waiting in review`. A committed fact says
`saved as a fact.`

## Default handshake change

Eleven tools in every handshake is how agents forget the loop. The host
now injects a brief, so the default surface is remember, recall,
continue. Capture and the pack stay real; they are not the default. Set
`ALICE_MCP_FULL_TOOLS=1` in the host env map to list them.

The eight non-default core tools, including `alice_capture` and
`alice_context_pack`, are missing unless `ALICE_MCP_FULL_TOOLS=1` is
set. Set the flag in the same host env map as the server. Hermes does
not inherit the user's shell; the flag belongs in the snippet `env`
map.

## Ranking and sleep

Present-tense recall and the session brief put the current committed
fact above a superseded ancestor of the same fact.

After the first FTS hit, `alice_recall` follows one provenance hop from
the shared source to linked committed facts, up to
`PROVENANCE_EXPAND_ONCE_MAX_TOKENS` (640). The hop writes into
`results[]`, not `sources[]`.

`compile_context_pack` picks a loops / facts / sources view from the
query when `budget_strategy` is left at default. `pack_view` is
disclosed when the query picks loops or sources, not on the default
facts envelope.

`alice-memory sleep` writes a capped sidecar of source proposals next
to the local SQLite db. It skips a source that already has an `active`
/ `accepted` fact and stops at 8. Rows stay `proposed`. The pass does
not rewrite imported notes or committed facts, does not change search,
and does not open the capture inbox.

## What this release does not claim

The LongMemEval 81.2% figure is a `v0.12.0` harness number from a
privileged `store_chunks` path that no MCP tool offers. This release
does not restate it as a product-path measurement. `pack_excerpts` is
named and not scored.

CI runs a continuity-task eval on a fixture vault. The receipt is
per-task pass/fail plus a count (`3/3`). That is not a LongMemEval
score and does not invent a percentage.

## Known limitations

Unchanged from `v0.15.7`:

- **`/v1` authenticates but does not authorize.** Keep it loopback-only.
- **Importers trust the directory you point them at.**
- **Archived import evidence is decoded text, not a byte image.** CRLF
  sources archive as LF.
- **Tool failures return a single generic code.** Every caller-facing
  failure reports `tool_request_failed` with no detail.

> Correction, 2026-09-25. This was not accurate when published: the server also reports `tool_not_found` and `tool_execution_failed`. None carries detail.

Known and deliberately not fixed here:

- **`alice_vnext_ingest_agent_output` still collapses whitespace in
  `content`.** Legacy surface only (`ALICE_MCP_LEGACY_TOOLS=1`). It does
  not reach the chunker.
- **An indented `#` line is treated as a heading by the chunker.**
  CommonMark would read a four-space-indented `#` as code.
- **Four read paths still compute a policy decision and do not fully apply
  it:** `alice_recent_changes`, `alice_resume_debug`,
  `alice_vnext_recent_memory_commits`, and `alice_project_dashboard`.
  None of them is a default tool.
- **Sleep does not accept a proposal.** Accept is a later commit.
- **`alice-memory sleep` writes a sidecar, not a memory.**
