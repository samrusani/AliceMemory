# Alice v0.11.1 Release Notes

> **Correction (2026-09-27):** the reviews these notes call independent were internal adversarial review, not an independent or external audit.

`v0.11.1` is the current uncommitted Phase 2 release-hardening candidate.
Its bounded local Python, PostgreSQL, SQLite, evaluation, web, and static
builder matrix was green at package-input freeze; final package reproduction,
a superseding carrier receipt, and independent review were still pending then.
Exact-SHA external release gates remain pending. Preparing this document does
not authorize a tag, package upload, or GitHub Release; `v0.11.0` remains the
latest published release.

## Default surface and public failures

- The required CI inventory gains an exact default-surface PostgreSQL smoke
  job. It explicitly omits `ALICE_LEGACY_SURFACES`,
  `ALICE_MCP_LEGACY_TOOLS`, and `ALICE_AGENT_API_KEY`, then exercises
  bootstrap, capture, recall, resume, context-pack, and review through the
  retained core surface.
- Surviving HTTP handlers return stable `detail.code` and `detail.message`
  values instead of exception-derived public text. MCP, CLI, and onramp
  failures, plus migrated provider, response, scheduler, evaluation, doctor,
  and connector diagnostics, use stable adapter-specific public vocabularies
  while retaining specifics in private logs. Intentional legacy-on
  `proxy_execution.py` business-result reasons remain dynamic and are
  explicitly excluded from this diagnostic migration.
- The OpenAPI registry documents the closed machine-readable error envelopes;
  dynamic exception text is not part of the public contract.

## Store and lifecycle correctness

- The `list_memories(query=...)` and `list_resume_memory_events(query=...)`
  legs used by recent decisions and resume now use the same ASCII case-
  insensitive literal-substring contract as open-loop filtering in PostgreSQL,
  SQLite, and unit fakes. Non-ASCII code points remain exact, and `%`, `_`, and
  `\\` remain literal query characters rather than SQL wildcards. Generic
  `search_memories` and `alice_recall` FTS/websearch retrieval semantics remain
  separate and unchanged.
- Terminal project-update replay uses store-side, target-filtered event
  lookups. PostgreSQL migration `0091` adds generated linkage columns and
  partial indexes; SQLite uses equivalent indexed union branches. Stable
  ordering and duplicate suppression remain part of the replay contract.
- Reject now fails before mutation when the mandatory candidate memory key is
  absent, matching accept. Generic HTTP, MCP, and CLI review/correct/forget
  paths also reject mutations that would strand a pending
  `project_auto_update` candidate.
- Source-identity normalization uses an explicit, locale-independent CPython
  3.12 whitespace table and defensive domain vocabulary rules rather than
  relying on database locale behavior.

## Coupled true redaction

- The owner-selected true-redaction design scrubs persisted copies coupled to
  a terminal project update: generated-artifact text and metadata, quality
  feedback free text, provenance quotes, memory fields, revisions, and decision
  events converge on exact content-free skeletons. All six numeric quality
  dimensions, categorical verbosity, and their structural audit identity
  remain.
- The same redaction verb is used through HTTP, MCP, and CLI. Repeating it is
  idempotent, and database guards prevent fabricated partial skeletons or later
  mutation of an already-redacted coupled record.
- Redaction does not roll back an accepted update already applied to
  `projects.current_state`. Alice source/source-chunk evidence is retained
  because it may support other memories and requires separate source hygiene.
  The operation also cannot retroactively erase upstream source systems,
  exports, or backups; those remain separate operator obligations.

## Debt and release-process sweep

- Store fakes reject unknown list filters and apply deleted-row parity. The
  development dependency set declares the minimum coverage version needed by
  the checker, release-body decoding is included in static analysis, and
  workflow-shape tests prove `publish-pypi.yml` has no `release:` trigger and
  remains manual `workflow_dispatch` only, while a one-shot scheduler passes
  `--once` to its child before spawn.
- `response_generation.py` is reduced to the behavior used by the retained
  provider runtime. Phase 1 already removed the empty web directories and
  documented import-time legacy-surface flags plus provider re-registration;
  the deleted entrypoint rate limiter makes the former shared-Redis flake
  obsolete.
- The repository keeps its bulk-advisory wrapper while Node 20 and pnpm 10 are
  pinned. Checkout and CodeQL actions use evaluated immutable revisions;
  incompatible major dependency candidates remain deferred for their own full
  compatibility carriers.

## Upgrade notes

- PostgreSQL migration `0091` adds stored generated columns and partial indexes
  to `event_log`. On a large database, adding stored columns can rewrite and
  lock the table; schedule the upgrade with an appropriate maintenance window
  and a verified backup.
- Migration `0092` installs the coupled-redaction guards and grants needed by
  the role-separated application path. Existing migrations through `0090`
  remain immutable.

79.4009% total and 62.9591% `main.py` coverage; 399 passing role-separated

flag-off default-surface smoke; 127 passing LongMemEval tests; all 78
provider-free SQLite eval cases passing in FTS-only mode; and 217 web unit plus
20 browser tests passing with type, lint, build, budgets, and both advisory
modes green.

85.8-85.9, and code-quality 83.1 (82.9 strict). The range reflects a documented
nondeterministic basename-only test-to-source mapping; it is not presented as a
favorable-point estimate.
