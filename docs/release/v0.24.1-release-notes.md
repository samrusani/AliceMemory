# Alice v0.24.1 Release Notes
<!-- alice-release-state: {"schema_version":"alice_release_document_state_v1","version":"0.24.1","publication_status":"pending","checksums_status":"pending"} -->

**This is a security release for installs that use agent keys on the PostgreSQL
stack. The SQLite vault behaves as before.**

## What to do after upgrading

1. **Upgrade the copy your hosts run** (`uv tool upgrade alice-memory` or
   `pip install -U alice-memory` in the environment they use), check it with
   `alice-memory --version`, and restart your hosts.
2. **Use an unbound admin key on `/v1`.** Once an active key exists, calls to
   `/v1` need an unbound `admin_agent` key. Other keys use `/v0/vnext` or MCP.
3. **Give your PostgreSQL MCP server its key.** Set `ALICE_AGENT_API_KEY` in
   the server's environment once the vault holds an active key.
4. **Review sensitive browser clips after capture.** On an install with active
   keys, a capability capture at `confidential`, `highly_sensitive`, `sacred`
   or `regulated` is refused. If appropriate for the clip, use `private` for
   capture and have the owner or an unbound admin key raise the label after
   capture.
5. **No database migration is needed.**
6. **Claude Code plugin.** The marketplace on `main` pins v0.24.0 until the
   change after publication moves it.

## The four changes

- **`/v1`.** On a PostgreSQL install with active keys, a valid unbound
  `admin_agent` key is required. Other valid keys receive HTTP 403.
  v0.24.0 served any valid key on `/v1`.
- **PostgreSQL MCP.** A server without `ALICE_AGENT_API_KEY` refuses tool
  calls, including reads and legacy tools, while an active key exists.
  v0.24.0 served keyless calls while active keys existed, although the
  [MCP guide](../alpha/mcp-tools.md) said those calls were refused.
- **Browser clip capabilities.** On an install with active keys, a capability
  capture is held to the strictest sensitivity ceiling among eligible
  issuers. A ceiling refusal leaves the capability available for another
  attempt before expiry. v0.24.0 applied no sensitivity ceiling to a capture
  made with a capability, even where the issuing key had a lower ceiling.
- **Mounted legacy `/v0`.** Every mode checks that the peer is loopback.
  v0.24.0 checked the peer only outside development and test.

## Behaviour changes an integrator will notice

On a keyed PostgreSQL install, a valid key that cannot use `/v1` receives HTTP
403, and a keyless MCP tool call that reaches the key check receives
`not_permitted`. A browser capture refused by the capability ceiling receives
HTTP 403 with `sensitivity_above_agent_ceiling`. A mounted legacy `/v0`
route refuses a non-loopback peer with HTTP 403.

## Security

This release was checked with automated security scanning and internal adversarial review, findings triaged and fixed. No one outside the project has audited the code.

On keyed installs the `/v1` check reserves operator access for a valid
unbound `admin_agent` key. The PostgreSQL MCP check closes keyless tool
access while a key is active. The browser capability ceiling prevents a clip
from exceeding the strictest eligible issuer's ceiling. The legacy peer
check keeps mounted `/v0` routes local in development and test as well.

A security advisory for the /v1 change is published with this release; it also names the PostgreSQL MCP change and the browser clip change. The v0.24.0 notes said that no security advisory was planned; that sentence is corrected here.

## What this release does not claim

- Mounted legacy `/v0` routes still serve local callers without a key or
  label filtering. See [known limitations](../alpha/known-limitations.md).
- In the supported deployment, `/v1` remains a loopback surface for the
  operator. See the [deployment guide](../deployment/single-tenant-self-hosted.md).
- The strictest eligible issuer ceiling applies to capability captures
  made on a keyed install even when an admin key issued the capability.
  See [agent integration](../alpha/agent-integration.md#authentication).

## Install

After publication:

```bash
pip install alice-memory==0.24.1 && alice-memory install
```

With uv: `uvx alice-memory==0.24.1 install`.
