# v0.4.0 Public Release Runbook

> Historical: kept for reference; not current guidance.

This runbook executes the closeout-aligned release readiness flow for the `v0.4.0` public tag.
Run it on merged `main` or on an explicit `v0.4.0` release-prep branch.

## Objective

Cut a credible public pre-1.0 release from the completed Phase 13 Alice platform with reproducible verification evidence.

## Scope Guard

Do not add features during this runbook. Only release-readiness, doc-alignment, evidence-recording, and tag-prep fixes are allowed.

## Step 1: Start Runtime

```bash
docker compose up -d
./scripts/migrate.sh
./scripts/load_sample_data.sh
```

## Step 2: Start API and Verify Health

```bash
APP_RELOAD=false ./scripts/api_dev.sh
```

Local/Lite startup now defaults to stdout logging with access logs disabled. For managed service installs, keep stdout and route retention through `systemd`/`journald`:

```ini
[Service]
Environment=APP_LOG_MODE=stdout
Environment=APP_ACCESS_LOG=false
StandardOutput=journal
StandardError=journal
```

Only enable file logging if an environment requires it explicitly. When that happens, set `APP_LOG_MODE=file`, provide `APP_LOG_PATH`, and keep `APP_LOG_MAX_BYTES` plus `APP_LOG_BACKUP_COUNT` configured.

In a separate terminal:

```bash
curl -sS http://127.0.0.1:8000/healthz
```

## Step 3: Run Release Gates

```bash
python3 scripts/check_control_doc_truth.py
./.venv/bin/python -m pytest tests/unit/test_control_doc_truth.py -q
./.venv/bin/python -m pytest tests/unit tests/integration -q
pnpm --dir apps/web test
./.venv/bin/python scripts/run_alice_lite_smoke.py
./.venv/bin/python scripts/run_hermes_memory_provider_smoke.py
./.venv/bin/python scripts/run_hermes_mcp_smoke.py
./.venv/bin/python scripts/run_hermes_bridge_demo.py
./.venv/bin/python -m alicebot_api --database-url "$DATABASE_URL" --user-id "$ALICEBOT_USER_ID" evals run --report-path eval/baselines/public_eval_harness_v1.json
```

## Step 4: Verify Public Docs

Check:

- `README.md`
- `CHANGELOG.md`
- `CONTRIBUTING.md`
- `SECURITY.md`
- `docs/quickstart/local-setup-and-first-result.md`
- `docs/integrations/mcp.md`
- `docs/integrations/hermes-bridge-operator-guide.md`
- `docs/archive/process/phase13-closeout-summary.md`
- `docs/release/v0.4.0-release-checklist.md`
- `docs/release/v0.4.0-tag-plan.md`

Ensure commands, claims, and release boundary match shipped reality.

## Step 5: Record Release Evidence

- update `docs/archive/process/BUILD_REPORT.md` with exact command evidence and outcomes
- update `docs/archive/process/REVIEW_REPORT.md` with closeout/release review state

## Step 6: Execute Release Checklist

Complete all checks in `docs/release/v0.4.0-release-checklist.md`.

## Step 7: Tag Gate

After checklist pass, reviewer `PASS`, merge approval, and explicit tag approval, follow:

- `docs/release/v0.4.0-tag-plan.md`

## Failure Handling

- If a required command fails, stop tag prep.
- Fix only release-readiness or closeout issues inside the current release-update scope.
- Re-run failed gates and update `docs/archive/process/BUILD_REPORT.md` before retry.
